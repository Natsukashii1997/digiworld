## 用户的初始构想（2026-10-05 原意整理）

知识仓库的两个目的：

1. **知识的统一源头**：知识库散在 Obsidian、飞书等处，全部接进这个应用。
2. **“我是谁”的统一源头**：个人底层角色说明只有一份，做成 MCP，让所有 Agent 读到同一份。

它**不是整理知识的页面，不存在加工**；就是“库”。

用户 2026-10-05 的决定：

- 知识源：Obsidian、飞书知识库（只读，需单独授权）、本机 Markdown 文件夹。
- 要**跨源统一检索**；知识也通过 **MCP** 提供给 Agent（只搜、只读，不写）。
- 个人说明区：正文预览、MCP 状态与接入配置、修改建议入口（建议仍在“待处理”采纳）。**不要读取记录**。
- **整理任务下线**（入口取消，已有数据保留不删）；**三区面板取消**（保留“个人说明文件夹”划分规则；篇数改在源节点上显示）。
- 理念为**数据中枢**（候选 B“总目录”未选）；检索在最上方。

## 1. 这页做什么

所有知识库与个人说明的统一源头：在这里查知识；把知识与“我是谁”统一供给所有 Agent。

## 2. 主角与类型

| 主角 | 是什么 | 怎么呈现 |
|---|---|---|
| 中枢（个人说明芯片） | 唯一的个人说明 + MCP 服务 | 中间一块芯片：`PROFILE · MCP`、MCP 运行状态点、最近修改、章节 / 字数、待采纳建议角标 |
| 知识源 | Obsidian / 飞书 / 本机 Markdown 文件夹 | 左侧节点：类型图标、名称、篇数、本周新增、状态（已连接 / 需重新确认目录 / 需授权）、是否开放给 Agent（锁） |
| Agent | 四只数码兽（同智能体群）+ 其他伙伴 | 右侧节点：头像、名称、已接入 / 未接入 |
| 检索结果 | 跨源命中的笔记 | 列表：源色标、标题、路径、两行摘录（命中高亮） |

## 3. 最常做的 3 件事

1. **跨源检索**：一个搜索框查所有已接入的库，结果按源筛选，点开只读原文（附“在 Obsidian 中打开”）。
2. **看接通状态**：哪个库断了、哪个 Agent 没接上。
3. **管理接入**：接新库、开放给 Agent、排除文件夹、复制 MCP 接入配置。

## 4. 信息层级（从上到下）

| 层 | 放什么 | 为什么 |
|---|---|---|
| 页头 | `07` `KNOWLEDGE` `部分可用` / **知识仓库** ? / 导语“所有知识库与个人说明的统一源头。”/ 标签：`只读` `开放给 Agent 需授权` / 右侧主操作“+ 接入知识库” | 飞书未接前保持“部分可用” |
| 检索 | 大搜索框 + 源筛选；有结果时结果列表展开在下方，把中枢图往下推 | 最常做 |
| 中枢图 | 左：源节点（末尾“+ 接入知识库”）→ 数据线 → 中：个人说明芯片 → 数据线 → 右：Agent 节点 | 汇入 → 统一 → 输出；状态一目了然 |

连线：亮线 = 已接通（源已连接 / Agent 已接入 MCP）；虚线 = 未接通（点 Agent 虚线复制该 Agent 的接入配置）。授权是全局开关，不按 Agent 分。

抽屉：

- **源节点**：目录、重新确认、断开、开放给 Agent 开关（默认关）、排除文件夹；Obsidian 源另含“个人说明文件夹”划分规则。
- **芯片**：个人说明正文只读预览（章节目录）、MCP 地址与一键接入配置、个人说明授权开关、“去待处理采纳建议 →”。
- **检索结果**：只读原文 +“在 Obsidian 中打开”。

## 5. 理念与形象

- **数据中枢**：左边各知识库的数据线汇入中枢，中枢的核心是个人说明芯片，右边的线通往各 Agent（数码兽）。
- 芯片用屏幕材质（它本身就是一块“核心屏”）；其余用面板材质。不用暴龙机外壳（只留首页）。

## 6. 动效与微交互

已接通的线上有光点缓缓流动；检索结果展开时中枢图下移；悬停节点时该节点的线高亮；减少动态效果时光点静止。

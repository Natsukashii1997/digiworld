## 用户对协同的定义（2026-10-05）

协同 = **多个 Agent 一起推进的复杂工作流**，是资产仓库里“工作流”的延伸 / 落地应用。现在常做的是 Claude + Codex 的协同工作流；以后可能有 Claude + Codex + Hermes 三方，或不同 Agent、不同情况下的不同协同方式。在每个工作流里，整个协同过程要**看得见**：哪个 Agent 干了什么、如何传递与交付；**阶段性有验收、有交付、有交接**。协同应是**标准、优质的工作流的完美实现**——每个阶段不仅写谁做，还要写清怎么做（例如 Claude 简报阶段使用 grill-me skill 深度梳理）。

## 1. 这页做什么

运行多 Agent 工作流，并把全过程摆在眼前：谁在哪个阶段做了什么、交付了什么、谁验收、结论如何、交给了谁。

## 2. 主角与类型

| 主角 | 怎么呈现 |
|---|---|
| 一次运行（项目 × 模板） | 顶部运行列表的一行：项目 · 事项 · 模板与版本 · 当前阶段 · 状态 |
| 参与者泳道 | Claude / Codex / 你（以后 Hermes），泳道头为数码兽头像（你为“用户”标识） |
| 交付物卡 | 落在执行者泳道 × 阶段的卡片：交付物名、编号、状态 |
| 交接连线 | 卡片跨泳道连线 |
| 闸门 | 过关节点：确认 / 通过亮绿，返修亮红并有回流线（“返修第 n 次”） |
| 当前阶段 | 发光；节点上挂“下一棒”发车条 |

## 3. 最常做的 3 件事

1. 看某次运行进行到哪、卡在谁手里。
2. 点节点看详情：执行者、方法 / skill、交付物链接（简报、视觉稿、派单、交接）、存档点、验收结论。
3. 在当前阶段“下一棒”：生成带方法要求的口令（如“请用 grill-me ……”“按派单冻结参照 ……”），复制或带到对应 App。

## 4. 信息层级

页头（`05` `WORKFLOW RUNS` / **协同** ? / 导语“多 Agent 工作流的全过程：谁做了什么、交给了谁、过没过关。”/ 标签 `以项目协议文件为准` `口令由你发送`）→ 运行列表 → 泳道流水线（模板名 + “在资产仓库查看模板 →”）→ 当前阶段发车条；节点详情为右侧抽屉。

## 5. 理念与形象

泳道流水线：横轴阶段、纵轴参与者；交付物卡沿流水线推进，交接是跨泳道连线，验收是闸门；去掉两台暴龙机（暴龙机外壳只留首页）。

## 6. 动效

当前阶段节点呼吸光；交接连线上光点流动；返修回流线红色虚线；减少动态效果时静止。

## 7. 390 取舍

运行列表单列；泳道流水线横向滚动（泳道头固定在左）；节点详情全屏抽屉；发车条吸底。

## 8. 不放什么

两台暴龙机、“建议下一步”等推断性长文、说明段落；不在工作台另存派发记录作为权威。

## 1. 这页做什么

读档：挑一个在推进的项目接着干；或从库里挑一个开新档。

## 2. 主角与类型

| 主角 | 是什么 | 怎么呈现 |
|---|---|---|
| 存档槽 | 在推进的项目（`active`） | 大卡：`SLOT 01` + 像素存档图标、项目名、持笔数码兽、**下一步**、阶段五步、30 天活动条 |
| 卡带 / 徽章 | 最近更新的 3 个**未在推进**项目 | 卡带版：像素游戏卡带，标签贴纸写项目名；徽章版：一个项目一枚像素徽章。底部英文等宽：`LOCAL` / `GITHUB` + 最近更新 |
| 紧凑列表 | 其余项目 | 一行一个：名称 + 路径（等宽小字）、状态、最近更新、“标为在推进” |

## 3. 最常做的 3 件事

1. **继续**：存档卡“继续” → 卡下方展开整行发车条（伙伴头像，默认当前持笔者，无人持笔默认 Codex；预览口令；只复制；带到 X 继续 →）。同一时间只展开一张，Esc 收起。
2. **看进度**：下一步、阶段、活动、是否停滞、有无安全问题。
3. **开新档**：卡带 / 徽章悬停抽出露出“开新档 →”（= 标为在推进）；列表行右侧同一动作。

存档卡细节：

- 持笔数码兽 = 当前写入者（智能体群同一套形象：Claude Code 机械暴龙兽、Codex 机械邪龙兽、Hermes 亚古兽、OpenClaw 加布兽）；写入者为“无” → 暗色剪影空位 + “无人持笔”。
- **下一步**是卡上最大的一段文字；阶段五步（认领 / 实现 / 复核 / 返修 / 验收）；30 天活动条。
- 安全问题：只有存在时卡角红点 + 数字。
- 停滞：整张卡睡着（变暗 + zzz）。
- 读不到 CURRENT：下一步位置写“读不到 CURRENT”+ 原因（文件不存在 / 格式不对 / 无权限），不当作停滞。
- 按钮：主按钮“继续”；文字按钮“详情”= 打开项目抽屉。

项目抽屉：顶部项目名、来源、最近更新；“状态”块（状态号、写入者、体检明细、GitHub）；其下“位置”“连接”“规则”三块（现有 ProjectLocations、ProjectContext、ProjectRules、标为在推进、打开 GitHub，内容功能全保留）；说明文字进「?」。

## 5. 理念与形象

- **RPG 读档画面**：在推进的项目 = 存档槽（章节 = 阶段，队伍 = 持笔者，存档时间 = 最近活动）；其余项目 = 卡带库 / 徽章墙，挑一个即“开新档”。与智能体群的“选角画面”同一套游戏语法。
- 编号用英文等宽 `SLOT 01` + 像素存档图标，不用液晶。

## 6. 动效与微交互

| 时机 | 动效 |
|---|---|
| 存档槽悬停 | 轻亮，数码兽待机动作 |
| 停滞 | 卡变暗，飘出 zzz |
| 开新档 | 卡带 / 徽章飞入空槽并点亮 |
| 继续 | 发车条从卡下方滑出 |
| 减少动态效果 | 全部直接切换 |

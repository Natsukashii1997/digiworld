状态：**用户 2026-10-05 已确认**（grill-me 三轮）；视觉稿 `pages/savepoints*.html` **用户已确认**；派单见 [排队：存档点](../../../agents/handoffs/2026-10-05-claude-dispatch-savepoints-queued.md)。

## 为什么改

- 用户“基本不来”原页面：资产版本时间线与资产详情的“历史”标签重复（同一组件），归档资产只是个筛选。
- 用户的设想：像“数码世界”这样最终要落地成应用的项目，需要用 **Git 管版本**，以防改来改去；以后的其他项目也要接进来。
- 现实风险（2026-10-05 只读核对本项目）：最近一次提交在 10/03（WB-20261003-123），此后 50 多次状态更新、104 个修改文件 + 180 个新文件均未提交；另有 2 个本地提交未推送。

用户 2026-10-05 的决定：

- 页面改为“**存档点**”（SAVE POINTS），管理项目的 Git 版本；与项目空间的“读档”呼应。
- **页面直接创建存档点**（预览 → 确认 → 只提交）；不推送（只显示未推送数）；不回退（只看、只对比、生成“回退口令”交给 Agent）。
- 项目来自项目空间扫描结果，新项目自动出现（项目清单与扫描后续会让 Codex 整理）；未开启 Git 的项目可“开启存档”（初始化 + 默认忽略规则 + 首个存档点，预览确认）；仅云端项目显示只读时间线。
- 原资产版本时间线只留在资产详情；已归档资产改为资产仓库“已归档”筛选（恢复功能随迁）；不汇总其他写操作留痕。

## 1. 这页做什么

给每个项目留存档点，以防改来改去：看还有哪些进度没存档、一键存档、翻看历史存档点。

## 2. 主角与类型

| 主角 | 是什么 | 怎么呈现 |
|---|---|---|
| 未存档进度 | 工作区未提交的改动 | 大面板：距上次存档多久、修改 / 新增文件数、增删行数、主要目录分布；按时间变色（>1 天黄、>3 天红） |
| 存档点 | 一次 Git 提交 | 时间线节点：说明、时间、改动文件数；自动识别说明中的状态号（`WB-…`）并链接对应交接；未推送的标“未上云” |
| 里程碑 | 打了标签的提交 | 更大的节点 + 标签名 |
| 项目 | 项目空间里的项目 | 本机 Git 项目 / 未开启存档 / 仅云端（只读） |

## 3. 最常做的 3 件事

1. **存档**：看未存档进度 →“创建存档点”→ 预览文件清单（默认全选，遵守忽略规则；疑似凭据、超大文件默认不勾并警告）与说明（有 CURRENT 的项目默认“状态号 · 当前任务”，否则“日期 · 主要改动目录”，可改）→ 确认，只执行提交。
2. **翻看**：点存档点看改动文件与统计，“与现在对比”；需要回退时“生成回退口令”。
3. **接入新项目**：未开启存档的项目点“开启存档”。

## 5. 理念与形象

与项目空间同一套游戏语言：项目空间是“读档”，这里是每个项目的“存档点”历史。节点用像素存档图标；未存档进度像“未保存的游戏进度”，时间越久越红。

## 6. 动效与微交互

创建存档点后新节点“存入”时间线顶端；风险色随时长渐变；减少动态效果时直接切换。项目空间的存档卡加“未存档 N 天”提示，点击跳到这里。

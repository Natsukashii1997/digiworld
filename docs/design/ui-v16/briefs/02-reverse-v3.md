## 1. 这页做什么

弄懂一件好东西。看得见的作品，放上鉴定台对照复刻；拆得开的软件，放上解剖台用 REA 取证。得到带证据的配方后，可以炼成 Skill，也可以落地到自己的项目。

## 2. 主角与类型

| 主角 | 是什么 | 在哪张台 |
|---|---|---|
| 作品 | 文字、图片 / 海报、网页（TXT / IMG / WEB），以及只有截图的功能 | 鉴定台：原件 ↔ 复刻对照 + 分项打分（即现有对照台） |
| 软件 | 本机 Electron 应用，或已在调试版 Chrome 中打开的网站（FN + REA 目标） | 解剖台：**证据链**是主角，配合未知项与验收用例 |
| 证据链 | 从界面入口到数据落点的一串节点（UI → RENDERER → IPC → MAIN → DATA 等），每个节点标观察 / 推断，并挂证据编号 | 解剖台中央 |
| 未知项 | 伙伴答不上来、REA 覆盖不到的问题 | 解剖台，黄色虚线框；0 条时不显示 |
| REA 装备 | 取证用的工具，有版本号 | 页头右侧的液晶读数 |

## 3. 最常做的 3 件事

1. 投入一个软件目标，交给 Codex 用 REA 取证，回贴后看证据链和未知项。
2. 选“独立复刻”还是“我的项目”，把实现任务交给伙伴，回来后逐条核对验收用例。
3. 到终点：达标后炼成 Skill；落地到项目后盖章，项目空间可见。

偶尔做：点页头读数检查并一键更新 REA。

## 5. 理念与形象

- 解剖台：软件被摊开，证据链像解剖图上的神经走向；青色连线表示已追到。
- 终点的两扇门：一扇孵出数码蛋（沿用像素蛋），一扇通往项目（橙色）。
- REA 装备读数是一块小液晶屏，因为它本身就是一台仪器的读数。

| 时机 | 动作 |

## 一键更新 · 行为约定（写派单时细化）

1. **检查**：读 GitHub Releases 最新正式版，并核对 npm `rea-agents` 已有同一版本（setup 走 npm；没同步时显示“发布同步中”，不提供更新）。当前版本以 `rea doctor` 读回的注册版本为准，工作台不直接解析 Agent 配置文件。
2. **预演**：运行该版本的 `setup --client claude_code --client codex --dry-run`，抽屉里列出将改的配置、Skill 版本和备份位置。
3. **适配检查**：确认任务包用到的工具和参数在新版仍然存在（`analyze_javascript_application`、`inspect_analysis_view`、`trace_application_feature`、`list_browser_targets`；`input_path` / `integrity_policy` / `detail` / `cdp_endpoint`）。缺任何一项就拦下更新，并说明缺了什么。
4. **写入**：常浩点“确认更新”后才执行 `--yes`，并且只针对预演时的同一个版本。
5. **回读**：用 doctor 确认两个客户端都已对齐新版本，读数刷新，提示重启。结果不明时先查询，不重复写入。
6. **失败态**：网络失败、发布同步中、适配不过、写入失败（备份位置可见）、回读不一致，每种都要有明确文案。
7. **边界**：只在点击时联网；不自动定时更新；不升级 Node、Hopper、Ghidra 等其他软件。

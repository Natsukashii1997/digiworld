## 规则

1. **返修分级**：小精修不阻塞，并入下一单；返修回第 4 站由 Codex 做；同一项第 2 次仍不过，升级给你决定（改稿 / 接受 / Claude 自做）。
2. **推进节奏**是每次运行的设置：“逐单停等”或“连续推进、最后一次验收”；线路图页头显示当前设置。连续推进只在阻断点停。
3. **功能问题**：开发中发现的缺接口 / 缺字段，当单只做最小诚实实现（不编造数据），记入该轮次的待议清单；轮末统一定结论，再开功能批次。
4. **运行粒度**：一张派单 = 一次运行；多次运行可归入同一“轮次”（如“UI v16”）；待议清单挂在轮次上。
5. **执行者**：模板定默认，开运行时可换人（如实现站换 Claude 或 Hermes）；线路图按实际执行者画泳道。
6. **版本**：模板在资产仓库“工作流”资产中编辑，改动生成新版本；进行中的运行锁定开工时版本，可手动“升级到新版”并先预览差异。
7. **过关依据**：只读并链接项目里的派单 / 交接 / 验收文件（以项目协议文件为准），工作台不另存结论；缺文件显示“未过关 · 缺依据”。

## 一、从资产仓库学什么

学的是**方法**，不是版式。资产仓库的形态来自它的内容本质：

- 逐条记录，所以一屏一屏地陈列；类型要区分得开。
- 形象来自用户的概念：Skill 是数码蛋（用了会成长），Prompt 是对话框。
- 层级分明：粗与细、大与小、中文与英文、有动效；几乎没有解释性文字。

每页要找到**最适合这一页**的呈现，不照抄对象墙。

## 二、全站统一的视觉基调

- 深墨蓝底；有来由的像素图标；克制的发光；数据对象用屏幕材质。
- 中英双层文字：中文粗标题负责“是什么”，英文等宽小字负责“编号 / 类型 / 状态”。
- 液晶元素只在“对象本身就是一块屏”时使用；空状态每页按自己的主角设计；暴龙机外壳只留首页。
- 页头语法照用资产仓库：编号 + 英文眉题 + 成熟度 + 中文大标题 +「?」+ 一句导语 + 最多 3 个边界标签 + 右侧主操作。
- 页面不放解释段落；说明进「?」弹层或抽屉。
- 每页同等认真，不按项目优先级分轻重。每页可以有自己的创新设计。

## 三、每页流程

1. **页面简报**（8 栏：做什么 / 主角与类型 / 最常做的 3 件事 / 信息层级及理由 / 理念与形象 / 动效与微交互 / 390 取舍 / 不放什么）→ 用户确认。
2. **1440 + 390 视觉稿**，数据丰满的状态为主，空状态单独一张 → 用户确认。
3. **落代码**：小页 Claude 直接做；大页派 Codex，前提是视觉稿画清所有状态（满、空、加载、错误、悬停），Codex 交回视觉稿与实现的 1440 / 390 叠图与逐区差异，Claude 逐区验收、偏差退回；同类页返工两次以上改由 Claude 自做。
4. 理念来源：用户有想法的页用户先说；没有的 Claude 提两个候选由用户挑。

## 四、顺序

智能体群（含能力体检）→ 逆向工程 → 学习成长 → 银饰 → 随手记 → 项目空间 → 知识仓库 → 版本归档 → 待处理 → AI HOT → 日历 → 夜巡 → 协同 → 设置 → 首页（最后，因为它汇总各页主角）。

已知要求：

- **随手记**所见即所得：选颜色直接显示颜色（不显示 `[文字]{red}`）；待办是一个方框，点一下打钩、文字划线（[参考](refs/notes-checkbox.png)）。
- **日历**重排：日历格不再与 todo 挤在一行。

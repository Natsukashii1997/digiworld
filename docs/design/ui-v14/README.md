## 一、用户决定（按时间，均为 2026-10-03）

1. 方向：**掌机里的数码世界**——每页是掌机里的一块屏幕；视觉美观、有趣、动效丝滑、层次丰富，整体协调。文字与配色认可。
2. v14c（按 Codex 评审重画的克制版）被否定：“过度修改，都不如上个版本”。**以 v14b 为底全部还原，含全部动效细节**（换台、液晶开机扫亮、像素涟漪、阶梯擦入、微光与倾斜、跑马灯、背景微尘、待机浮动等）。
3. 从 v14c 保留且**非常认可**：①“一次局部反馈”动效（液晶窗翻转一次 + 旁边“已更新”）；②“三区视图”样式（ZONE MONITOR 设备屏、同一读数窗、同刻度占比条）。
4. 从 v14c 保留结构、**要求加强特效**：智能体群角色档案（左角色、右擅长/成本/常驻 + 内容检查）。v14d/e 已加强：像素逐行载入 + 扫描光带、地面倒影与发光地面、待机浮动、内容检查改为液晶读数条（开机扫亮后翻转一次）。
5. **协同完全重新设计**（v14b 赛道、v14c 流程图都不满意）→ v14d/e“暴龙机数据对接”：持笔机 ↔ 下一棒机，连接线上是阶段灯，返修为复核下方的条件回路，派发口令 = 一次数据传输（数据包沿线传到右机、屏幕翻转显示 TRANSFER OK、记录新增“你 → 下一棒”）。用户看过后未提修改，随即要求交接落地。
6. 首页**删除“今日”区**（日弧、日程块、待办全部不要）；主卡之后直接从“待处理”开始。
7. **银饰页最后**，本轮不动。
8. 角色素材为**占位**（项目现有拼豆图纸素材），用户将重新生成一批；Agent ↔ 角色映射**待用户决定**（预览中候选 A / 候选 B / 字母牌可切换，全站同步）。

**约束**

- 只改视觉与前端呈现，不改业务逻辑、数据口径和服务端接口；按钮名与测试依赖的文字尽量保持，需求变化导致的断言调整写进交接。
- 控件至少 44px；窄屏 320/390 无横向溢出（逐元素检查，不靠 `overflow-x: hidden` 掩盖）；axe 通过；系统“减少动态效果”时 CSS / SVG / Canvas / JS 动画全部停（含运行中切换）。
- 角色渲染：原色、整数倍；头像 = 头部裁切 1×，名册 = 全身 1×，档案 = 全身 3×；素材数据集中在一处，换素材只换数据。映射未定前按候选 A 实现并保留切换口子，或先用字母牌——开工前问用户。
- 预览里的数据是合成的。以下视觉元素**需要新的只读数据**，现有接口没有，落地时先登记缺口、问用户是否另开切片，不得编造：项目卡“近 30 天活动”按天热力；三区“近 7 天”按天趋势（现有 `zoneStats` 只有本周合计）；首页待处理“1 件卡住了项目”这类派生摘要。
- 知识页“统计三区”、角色档案切换、协同派发成功使用“一次局部反馈”；失败与未知用稳定提示，不闪。
- 首页“今日”区删除后，`HomeSchedule`（日历今日块）不再出现在首页；日历页本身不变。
- 银饰页不动。

**建议顺序**：公共层（令牌、液晶点阵组件、结果反馈、精灵渲染与映射）→ 知识仓库 → 项目空间 → 协同 → 智能体群 → 首页。每页完成后跑 `npm test`、全部浏览器脚本、`tests/visual.mjs`，并给用户前后截图对比确认。

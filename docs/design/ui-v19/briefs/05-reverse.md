## 1. 这页做什么

回答一件事：**从这件参照物里拆出来的 Skill，现在有了哪几块，还缺哪几块。**

- 缺的格子一键写成下一轮追问包，复制给原生 Agent（Codex / Claude Code）去拆。工作台不自己取证，也不调用模型。

## 4. 数据口径

### 4.1 八格怎么来

- 任务包要求 Agent **按八格回答**：每格写「已知」和「缺」，缺的部分写成问题。
- 放回结论时，按八个小标题拆进格子：只有已知 = 填上；已知和缺都有 = 半格；只有缺或没写 = 空。
- 格子正文可以手改。手改的格子标「你改过」，下一轮结论不覆盖它。

### 4.2 追问包

- 内容：参照物、想弄懂、上一轮已经知道的、这一轮只回答的问题（来自勾上的格子），以及八格回答格式。
- 预览和复制用同一个字符串，过滤凭据。
- 只复制，不自动发送。复制后，勾上的格子标「第 N 轮在问」。

### 4.3 孵化

- 什么时候都能孵，不设门槛。空着的格子写进 Skill 的「局限」，并注明「未经复刻验证」。
- 沿用现有的「预览 → 确认 → 同 revision 写入固定版本 → 回读」。同一状态重复确认，复用已存的版本。
- 资产版本带来源 `origin: {kind: reverse, id}`。

### 4.4 旧记录

旧版本的结论没有分格（例如 10/16 那份）。显示为「旧结论 · 未分格」，并提供「让 Agent 按八格整理」：生成一份只整理、不重新取证的任务包。原证据和任务包版本只读保留。

## 6. 状态与异常

| 情况 | 呈现 |
|---|---|
| 新标本，还没交出 | 只有用途格填上，其余 7 格空；蛋没有裂纹；每轮条写「还没交出」；追问包是「完整取证」 |
| 上一轮失败或被挡 | 来源条写失败原因；格子不变；追问包默认带上「先确认目标能打开」 |
| 在问，还没回来 | 格子和接口灯是青色；孵化器提示「回来了就放回结论」 |
| 放回的结论分不出格 | 整段放进「未分格」区，提示「让 Agent 按八格整理」 |
| 孵化写入失败或回读不一致 | 不推进状态，预览保留，提示重试；不重复写入 |

## 7. 动效

全部按帧，有因果，一次到位。用户开了「减少动态效果」时直接显示最终状态。

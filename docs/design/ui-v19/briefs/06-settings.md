## 1. 这页做什么

一年打开没几次，打开时只想知道三件事：**现在放出去了哪些权限、数据有没有备份好、哪里不对劲**；要改时在同一行改完，立刻看到结果。

## 2. 主角

**一张开机自检清单，每行一项，右端就是它的操作。** 不分页、不展开、没有左栏。

| 元素 | 是什么 | 怎么呈现 |
|---|---|---|
| 自检头 | 这次自检的时间 | 一行：`POST · 数码世界 · REV 946` · `自检完成 · 10 项 · 11:32` |
| 自检行 | 一项设置的现状 | `[标记]` · 名字 · 一句结果（等宽字）· 右端操作。标记：✗ 要处理（红，整行淡红底 + 左边红条）、! 要看一眼（黄 + 左边黄条）、● 外部访问开着（青）、✓ 正常（绿）、· 还没配置（灰）。问题排最上 |
| 右端操作 | 这一行唯一要做的事 | 按钮或开关，最多两个：下载恢复包（橙，全页唯一橙色）/ 知道了 + 开关 / 开关 / 系统设置 / 调整 / 添加目标 |
| 数据行 | 不常用的数据操作 | 清单底下一行：导出可合并数据 JSON · 导入备份 · 在访达中显示 ··· 最右「从完整备份恢复…」（红边） |
| 计数 | 一眼的结论 | 底部三个液晶：要处理 / 要看一眼 / 正常，右边一句「还有 1 项要处理，2 项要看一眼」 |

## 3. 最常做的 3 件事

1. **看哪里不对**：开页自检跑完，红黄的在最上，底部一句结论。
2. **拨一个开关**：点开关 → 右侧（手机底部）抽屉写清会授予什么、当前状态与最近使用 → 确认后才拨过去。
3. **备份一次**：点「下载恢复包」，这一行翻成 ✓。

## 4. 信息层级及理由

| 层 | 放什么 | 理由 |
|---|---|---|
| 页头（一行） | 设置 SELF-TEST · 读取时间与 REV · 重新自检 | 现版页头约 180px（eyebrow + 大标题 + ? + 导语）；这页不需要介绍 |
| 自检清单 | 10 行，问题排最上 | 「哪里不对」就是第一眼要知道的；每行的操作就在旁边，不用先找分区再找表格 |
| 数据行 | 导出 / 导入 / 访达 + 恢复 | 偶尔才用；恢复会换掉整个工作台，和普通操作分开、红边、要单独确认 |
| 计数与结论 | 三个液晶 + 一句话 | 处理完一项马上看到数变 |

判定规则（落代码时由真实读数算，不写死）：
- ✗ 完整备份：`/storage/status` 的 `lastBackup.state` 为 `none`（从未成功）。
- ! 某项能力：`/capability-usage` 里最近一次使用结果为失败或未知，或 `/capabilities/settings/history` 里最近一次申请未生效；用户点「知道了」后翻 ✓（记在哪见待确认 2）。
- ● 外部访问开着：能力已开启（`/capabilities/settings/status`）、日历已授权（`/calendar/status`）、AI HOT 允许访问（`/aihot`）。
- ✓ 关着且没有异常记录；· 还没有可配置的对象（资产交付目标 0 个）。

## 5. 视觉理念

**暴龙机开机自检**：一行一项，`[✗] [!] [●] [✓] [·]` 是唯一的状态语言，结果用等宽字，像机器自己报出来的。做工按全站 v19：面板不透明、单层边框、只有液晶和指示灯自己亮；橙色只给「下载恢复包」；红色只给要处理和恢复。不画记忆卡、旋钮、开关排这些装饰块。

## 6. 动效与微交互（按帧，减少动态效果时直接到位）

| 时机 | 动效 |
|---|---|
| 进页 / 重新自检 | 每行先出名字，后面「. → . . → . . .」三帧，再出标记、结果和操作；一行约 0.2 秒，跑完底部计数从 00 翻到真实数 |
| 拨开关 | 抽屉按帧滑入（手机从底部）；确认后拨片三帧滑过去；这一行标记按帧 ✓ → ▒ → ░ → ●，结果句更新，计数翻页 |
| 下载恢复包 | 按钮里四格进度按帧填满（▮▯▯▯ → ▮▮▮▮），这一行 ✗ → ▒ → ░ → ✓，结果写「刚刚下载过恢复包 · 请确认已存到磁盘」 |
| 知道了 | 这一行 ! → ✓，按钮变「已看过」 |
| 调整 / 添加目标 | 抽屉滑入；步进器的液晶数字按帧翻页；完成后这一行结果更新并闪一下 |

## 7. 手机端（390）取舍

- 侧栏收起，顶栏：菜单键（打开侧栏抽屉，伙伴屏随侧栏）· 数码世界 / 设置 · 搜索。
- 页头：标题 + 重新自检；读取时间去掉。自检头只留「自检完成 · 10 项 · 时间」。
- 每行两层：上层标记 · 名字 · 右端操作；下层结果句（可换行，不截断）。
- 数据行折成多行，「从完整备份恢复…」整宽一行放最后。
- 抽屉从底部升起（最高 86% 屏高），取消 / 确认各占一半。
- 计数一行，结论句另起一行。控件都不小于 44px；页高 1364（1440 下 931）。

## 8. 不放什么

- 不分页、不要左栏分区（授权与安全 / 数据与备份 / 项目设置 / 资产交付目标 / 历史授权五个分区合并成一张清单）。
- 不放「最近一次使用」「操作」这种整列都一样的表头列；不放「部分可用」徽章和页面导语。
- 不放记忆卡块格、旋钮区、开关排（二 · 后盖面板的做法，用户没选）；不用点开才能操作（三原稿与 3-2 的做法）。
- 「恢复记录无法核验」不作为常驻问题：那是隔离副本触发的，正式环境要发 POST 才能查；落代码时按真实查询结果决定是否出现。
- 不放通用「左栏 + 表格 / 清单 + 网格」版式（10-24 已否）。

- 行上的状态与最近使用 = 现版 `src/settings-v16.js` 的 `permissionRows`；**已开启的计数要把 AI HOT 算进去**（现版首屏「N 项已开启」漏了它）。

## 10. 3 个待确认（用户 2026-10-24：都按推荐）

1. **知识开放这一行用一个开关还是「管理」？** 现版是每个来源各自开放（Obsidian知识库、常浩的知识库、个人说明 MCP 各有一个开关），稿里一枚开关对不上。**推荐**：行内开关换成「管理」按钮，抽屉里三个来源各一枚开关、各自预览确认；行上结果写「3 个来源都关闭 · 10/23 23:38 Claude 读取失败」。
2. **「知道了」记在哪？** **推荐**：只记在本机界面（按那条使用记录或申请记录的编号记住），不写主库；以后出现新的失败或未知记录，这一行再亮黄。
3. **现版有、稿里没画的入口放哪？** 模型 / API 与常驻服务的「管理」（凭据、服务运行状态）、旧版浏览器数据「检查并导入」、页头「?」帮助。**推荐**：「管理」放进这一行的预览抽屉底部（「管理凭据…」「查看服务状态…」）；旧版浏览器数据只在检测到时出现在数据行；「?」帮助放到「重新自检」旁边。

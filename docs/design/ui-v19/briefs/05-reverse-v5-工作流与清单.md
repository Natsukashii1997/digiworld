## 0. 为什么重做

用户 10-31 的判断（经分析后确认）：
- 拆解在 Claude Code / Codex 里用 REA 做，工作台不参与过程。之前几轮把这一页做成「主舞台」，用画布、照亮、孵化器、星图来装扮，形式大于实际。

- 真正有价值的只有两件事：
  1. **把 REA 逆向固定成标准工作流**：每次想逆推一个新功能，在工作台一键生成写好的标准话术，复制出去就能开工；需要你确认的地方，有提示。
  2. **留存清单**：每次逆向最后产出了什么、什么值得留下来，都收进工作台，以后能找到、能交给 Agent 用。

## 1. 这页做什么

一句话：**从这里开始一次逆向，最后产出留在这里。**

| 做 | 不做 |
|---|---|
| 新建一件参照物，生成开场话术，一键复制给 Codex / Claude Code | 工作台自己取证、调用模型、跑 REA |
| 每个阶段给出下一步该复制的话术 | 实时监控 Agent 拆到哪了 |

| 清单里每件能看到：拆出了什么、证据、复刻对上没有、产出的 Skill | 编造进度数字（比如「照亮 10/19」这种分母由 AI 随口决定的读数） |

## 2. 标准工作流

六步，固定写进话术。**⏸ 是停顿点**：Agent 到这里必须停下来把东西交给你，等你回一句话才继续。中间要你确认的提示就落在这些停顿点上，所以出现在 Agent 的对话里，不在工作台页面上（工作台看不到 Agent 的过程）。

| 步 | 做什么 | 停顿点（Agent 停下来问你） | 你回什么 |
|---|---|---|---|
| 0 | 确认参照物能打开，确认是要分析的那个功能 | 打不开或对不上就停，说明原因 | 换地址 / 「继续」 |
| 1 | 拆前计划：列 3–7 项要拆的能力，每项写清想弄懂什么 | ⏸ 交能力清单 | 增删后回「开始」 |
| 2 | 取证：用 rea MCP 只读取证，每条结论标证据编号 | — | — |
| 3 | 交回执：按固定格式写（§3） | ⏸ 交回执：调 `reverse_report`，调不了就整段贴出来 | 「追问 …」/「复刻」/「先到这」 |
| 4 | 复刻验证：在临时目录做最小版，逐项和原版对照 | ⏸ 交对照表 | 「写 Skill」/「修 …」 |
| 5 | 写 Skill：按 SKILL.md 格式写，交回工作台，不直接装进任何 Agent | ⏸ 交 Skill 草稿 | 在工作台存 |

工作台只在阶段之间提示一句「下一步该你做什么」，例如：回执待你过目、可以派复刻了、Skill 草稿待存。

### 2.1 开场话术初稿

工作台用参照物、想弄懂、好在哪里（选填）三项填进模板，一键复制。

```text
# 逆向任务：{想弄懂}
参照物：{链接 / 本机路径 / 素材说明}
想弄懂：{想弄懂}
好在哪里（我为什么想拆它）：{选填，没有就删掉这行}
任务编号：{记录 ID}（交回执时带上）

请按下面六步做，⏸ 处必须停下来等我回复，不要跳步。

0. 先确认参照物能打开、是我说的那个功能。打不开或对不上就停下告诉我原因。
1. 拆前计划：列出要拆的能力（3–7 项），每项一句话写清要弄懂什么。⏸ 把清单发给我，我回「开始」再取证。
2. 取证：用你本机已注册的 rea MCP 只读取证。每条结论标证据编号（E1、E2…），写清证据在哪（文件 / 函数 / 请求 / 截图）。
3. 交回执：按下面「回执格式」写。写完调用工作台 MCP 工具 reverse_report 交回（带任务编号）；调不了就把整份回执贴出来。⏸ 等我回复。
4. 复刻验证（我说「复刻」才做）：在 ~/Sandbox/{日期}-{参照物简称}/ 里照回执做一个最小版，逐项和原版对照：一致 / 有差异（差在哪）/ 未验证（为什么）。⏸ 交对照表，同样走 reverse_report。
5. 写 Skill（我说「写 Skill」才做）：按 SKILL.md 格式写，包含用途、做法、关键证据、局限。只交回工作台，不要装进任何 Agent 配置。⏸

边界：
- 只读分析：不修改目标、不登录、不提交表单、不读我的私人数据和凭据。
- 没把握的写进「缺」，不要猜；推断要标「推断」。
- 复刻只在 Sandbox 目录里做，不改任何项目文件。
```

继续时用的短话术（每个阶段一条，带任务编号），由工作台按阶段生成：追问下一轮（只问勾上的缺口）、开始复刻、写 Skill。

## 3. 回执格式（固定，工作台按小标题解析）

**拆解回执**（步骤 3，每轮一份）：

```text
## 回执 · {参照物} · 第 N 轮 · 任务编号 {ID}
一句话结论：…
## 能力清单
- {能力}：已知 … ｜证据 E1, E3 ｜缺 …
## 八格
## 用途
已知：… / 缺：…
（结构、数据、流程、界面、边界、写入与回滚、验收，同样两行）
## 证据
- E1：{位置} · {说明}
## 下一轮建议问
1. …
```

- 八格沿用现有 `SLOTS`，现有放回解析（`ANSWER_FORMAT`）可以直接复用。
- 「能力清单」「证据」「下一轮建议问」是新增的小节。

**复刻对照**（步骤 4）：每项能力一行，写一致 / 有差异 / 未验证，外加复刻位置。
**Skill 草稿**（步骤 5）：完整 SKILL.md 正文。

## 4. 回执怎么回来

两种都留，进记录前都先预览、再确认，写入后回读：

| 方式 | 怎么做 | 依据 |
|---|---|---|
| A. 自动（主） | AI 调用工作台 MCP 工具 `reverse_report(taskId, kind, text)`，回执先进「待过目」，你在工作台预览后采纳 | 照现有 `propose_profile_change` 的做法：AI 只能提交，采纳由你决定 |
| B. 手动（兜底） | 把 Agent 最后一段回复粘贴进来 | 现有「放回」流程 |

## 5. 清单页

### 5.1 列表（页面主体）

每件参照物一行：

| 字段 | 说明 |
|---|---|
| 参照物 | 昵称 · 类型（网站 / 桌面应用 / 本机文件 / 其他） |
| 想弄懂 | 一句 |
| 阶段 | 计划中 · 已派出 · 回执待过目 · 复刻中 · 已收成 · 搁置 |
| 轮次 | 第 N 轮 · 最近日期 · 谁做的 |
| 产出 | Skill 名 + 版本（链到资产仓库），没有就写「—」 |
| 下一步 | 一句话 + 一个按钮（复制对应话术 / 过目回执 / 存 Skill） |

页头只放：「＋ 拆一件新东西」、待过目数（有回执等你看时才显示）、筛选（全部 / 进行中 / 已收成）。

### 5.2 点开一件：拆解档案

自上而下：
1. **头部**：参照物、想弄懂、好在哪里、阶段。
2. **结论**：最新一轮的一句话结论和能力清单。每项写已知、缺，证据号可点开看原文。
3. **八格**：当前已知 / 缺（取各轮合并后的结果）。
4. **复刻对照**：每项一致 / 差异 / 未验证，附复刻位置。
5. **产出**：Skill（版本、给哪个 Agent 用、使用口令、导出分享说明）。
6. **历次**：每轮派出的话术和交回的回执原文，默认折叠。

### 5.3 新建

一个小表单：参照物（链接 / 路径 / 素材）、想弄懂、好在哪里（选填）。提交后直接显示生成的开场话术，下面两个按钮「复制给 Codex」「复制给 Claude Code」。**从点「＋」到复制完成不超过 3 步。**

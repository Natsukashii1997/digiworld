## 一、我对需求的理解（10-24 纠正后）

第一版报告把“不如牛马之家”理解成“照着牛马之家做”，三个方向里两个把深色数码世界换掉了。这是误读。纠正后：

1. **数码世界的风格不变**：深色数码空间、液晶读数、像素图标、暴龙机、数码蛋、数码兽、存档槽、“捕获 / 炼化 / 出战”的说法，都留下。重做的不是世界观，是它的**做工**。
2. 真正要解决的是三件事，牛马之家只是对照出了差距：
   - **质感**：现在是“霓虹全息”——发光边框、半透明面板、渐变、光晕、网格地面，看着飘，所以“不实在”。
   - **舒适度**：青、橙、红、紫、绿、粉同屏，文字灰蓝压在深蓝上对比不够，还有一直在动的走线和光环，所以“容易疲惫”。
   - **信息密度**：每页页头约 180px，首页 40% 面积是不承载信息的暴龙机和徽记，资产页一屏只看到 3 张卡。
3. 品质标准：工具类应用，对标同类最好的深色界面（Linear、Raycast 这一类：密、清楚、克制），用数码世界自己的语言做到那个水准，不换成别人的语言。
4. **形式从内容本质出发**：每个世界观元素都要对应一个真实状态——蛋 = 没处理的捕获，存档槽 = 在推进的项目，数码兽 = 持笔者，装备 = 出战过的资产，液晶 = 真实计数。对应不上的（8 个徽记、轨道、走线、类型计数 0、页面编号）去掉。
5. 一页一页来，先做世界总览；每页 3 版视觉设计供选择；先简报，再视觉稿，再代码；不改功能和数据。

一句话：**从“霓虹全息”换成“实体机器”**。暴龙机、伙伴屏本来就是一台塑料外壳 + 液晶屏的实体设备，伙伴屏之所以是你最满意的，正因为它是哑光的、像素严丝合缝的、调色板克制的、动效有因果的——全站向它看齐，看齐的就是这个。

## 六、逐页诊断

### 1. 世界总览（现名“基地”）—— 判定：**重设计**

- **给谁用**：每天打开工作台的你本人。
- **主角应该是**：在推进的项目（下一步是什么、有几条需求等着交给它、点一下继续）。
- **最常做的 3 件事**：继续某个项目；记一笔；把待处理的念头 / 收藏投递出去。

| 维度 | 现状 |
|---|---|
| 视觉层级 | 最大最亮的是暴龙机和 8 个徽记，约占内容区 40%，不承载信息；在推进的项目在这页上根本没有 |
| 排版 | 左“资产仓库”7 格类型计数（3 格是 0）+ 最近更新（第一条是测试资产“111”）；右“收藏”3 条；都不能直接行动 |
| 留白 | 两侧面板下半截空着，中间被装饰填满 |
| 色彩 | 青、橙、红、紫、绿、粉 6 种颜色同屏，外加发光 |
| 动效 | 走线、光环、浮动一直在动，和你的动作无关 |
| 微交互 | 能做的只有记一笔和“新建资产” |
| 响应式 | 390 宽首屏全被暴龙机占满 |
| 原创性 | 有记忆点，但记忆点和用途无关 |

**为什么是重设计**：主角错了。这页该回答“今天从哪儿开始”，现在回答的是“我有一台暴龙机”。批一的 B 稿把内容改对了（加了待孵化、出战中），但暴龙机仍在中央、发光和网格仍在，所以还是“不实在、累眼”。

### 2. 随手记 —— 判定：**重设计**（世界总览之后再出方向）

- **给谁用**：你本人；实际用途是项目需求收件箱。
- **主角应该是**：还没处理的那几条，以及每条要交给哪个项目。
- **最常做的 3 件事**：记一笔；回看长清单；投递 / 归档。

1. 10 个筛选标签有 6 个是 0，占了一整行。
2. 胶带便签两列瀑布流：便签歪着摆、胶带颜色随机，长清单被截断要点“展开全文”；1440 宽一屏只能读 4 条左右。
3. 哪条已投递、投给谁，只是一个小标签；“待孵化”才是这页最该突出的状态。
4. 390 宽：页头 + 三行筛选标签 + 输入框占掉上半屏。

便签的“物件感”可以留（你 10/23 D5 定过），但要换成同一套实体材质：不歪、不透明、一种胶带。

### 3. 资产仓库 —— 判定：**重设计**（随手记之后）

- **给谁用**：要把 Prompt / 规则交给 Agent 的你。
- **主角应该是**：资产的名字和用途，以及“复制”。
- **最常做的 3 件事**：找到某个 Prompt；复制；看它被用了几次 / 改版本。

1. 卡片信息顺序颠倒：上半部 130px 是像素图标和一个没有标签的大数字，名字和用途在下面。
2. 复制不在卡片上，要点进详情。
3. 1440 宽一屏只能完整看到 3 张卡（共 8 份）；390 宽第一屏只看到 1 张。
4. Skills 0、工作流 0 占着筛选位。

保留的优点：类型形象来自你的概念（Skill = 数码蛋、Prompt = 对话框）、中英双层文字、进化阶段。

**这页的本质**：一年打开没几次。打开时只想知道三件事——**现在放出去了哪些权限、数据有没有备份好、哪里不对劲**；要改的时候，改完立刻能看到结果。参数（目录、阈值、交付目标）是偶尔调一次的旋钮。

**诊断（1440 / 390 实看）**：
1. 最要紧的状态被埋了：「上次完整备份：尚无成功记录」是第二分区里的一行灰字；「恢复记录无法核验」的红框和「恢复连接尚未核实」也在里面，不点进「数据与备份」就看不到。
2. 首页说「0 项已开启」，可「历史授权」里 AI HOT 网络访问是**已开启**——总数不含它，第一眼的结论是错的。
3. 同一类权限两个入口：知识开放给 Agent ↔ 历史授权的知识与 MCP；日历与提醒事项 ↔ 历史授权的日历与提醒。
4. 授权表的两列不带信息：六行都是「关闭」「从未使用」；操作列「预览开启」「管理」样子一样，有的行叠两个按钮，行高忽高忽低。
5. 危险操作和普通操作一样重：「从完整备份恢复」（覆盖整个工作台）和「下载恢复包」并排、同样式。
6. 通用 SaaS 版式（左栏导航 + 表格），没有这台机器自己的样子；页头约 180px，同全站共性问题。
7. 390 要横滑胶囊切五个分区，看全状态要滑四次。
保留的优点：「开启前先预览」的规则与每次外部写入单独确认；主库路径、REV、大小这些真实读数；每项都写清影响范围。

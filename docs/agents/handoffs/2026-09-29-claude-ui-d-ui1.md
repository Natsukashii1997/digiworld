# Claude → Codex｜D-UI1 修复：641–960px 顶栏标题挤压

- 输入 **WB-20260929-60**（[Codex UI v12.1 复核](2026-09-29-codex-review-ui-v12.1.md)，有条件通过）→ 认领 **WB-20260929-61** → 输出 **WB-20260929-62**，写入者已释放。
- 执行者：Claude；日期：2026-09-29。

## 原因

屏幕宽度在 641–960px 之间时，侧栏已经收起，但顶栏里仍然同时放着完整面包屑、“127.0.0.1 · 仅本机”状态，以及最小宽度 240px 的搜索框。标题没有剩余空间，被挤成多行，在 641px 时有一部分超出顶栏被裁掉。

原有视觉脚本只检查整页横向溢出和 axe，所以没有发现这类竖向裁切。

## 修复（仅 `src/styles.css`）

- **所有宽度的通用保护**：标题 `flex: none` 且 `white-space: nowrap`，保证不收缩、不换行；面包屑 `flex: 1 1 auto`；搜索框 `flex: 0 1 auto` 且 `min-width: 120px`。空间不够时由搜索框让出宽度。
- **641–960px 时提前切换为紧凑顶栏**：隐藏本机状态和面包屑的根级“数码世界”，搜索框宽度改为 `clamp(160px, 30vw, 240px)`。这里使用区间媒体查询，避免覆盖 ≤640px 下只显示图标的规则。
- **≤640px**：搜索按钮补上 `min-width: 44px`，确保新增的 120px 下限不会把手机上的图标按钮撑宽。

实测 11 个宽度（320 / 390 / 640 / 641 / 700 / 768 / 900 / 960 / 961 / 1024 / 1440），见 [topbar-widths.log](evidence-2026-09-29-claude-ui-d-ui1/topbar-widths.log)：标题均为单行（高 21px），并且完整位于顶栏内，没有横向溢出。搜索框宽度：手机上 44px，641px 时 192px，1440px 时 346px。

## 回归防护

`tests/visual.mjs` 新增临界宽度检查，覆盖 640、641、700、768、960、961 六个宽度。每个宽度下断言顶栏标题完整位于顶栏内、只占一行，并且没有被截断。

先写测试、确认它能失败：修复前运行，641 和 700 两个宽度报错，与 Codex 的复现一致；修复后全部通过。

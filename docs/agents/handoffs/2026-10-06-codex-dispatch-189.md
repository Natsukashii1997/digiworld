## 二、先写契约 `SAVEPOINTS.md`（再实现）

Git 能力是新的**写入面**，契约须写清：

- **只读**：工作区状态（修改 / 新增 / 删除文件数、增删行、按顶层目录聚合）、最近提交时间与说明、提交列表（分页）、标签、单个提交的文件清单与统计、与工作区对比、本地领先远端的提交数。仅限项目空间已登记、身份无冲突的本机目录；不读源码正文用于展示以外的用途。
- **写入只有两种**：
  1. **创建存档点** = 对所选文件 `git add` + `git commit`（说明由用户确认）；
  2. **开启存档** = `git init` + 写入默认 `.gitignore`（不存在时）+ 首个提交。
  两者都必须：预览 → 用户确认 → 执行 → 写后回读（新提交哈希、工作区状态）；未知结果先查询再决定，不盲目重试；同一项目同一时间只允许一个写操作。
- **明确不做**：push、pull、fetch 以外的远端写、reset、checkout、revert、rebase、stash、branch 删除、修改 git 配置与钩子。仅云端项目全部只读（沿用 GitHub 只读通道）。
- 预检：遵守 `.gitignore`；疑似凭据（文件名与内容特征，复用现有凭据过滤）与超大文件（默认阈值 50 MB）**默认不勾选并警告**；子模块、LFS、合并冲突中、HEAD 游离等异常状态一律只读并说明原因。
- 存档说明默认值：项目根有 CURRENT.md 且可读 → “状态号 · 当前任务（截断）”；否则 “日期 · 主要改动目录”。
- “生成回退口令”：只生成交给 Agent 的文本（目标提交、当前未存档改动提醒、建议先创建存档点），不执行任何 Git 命令。

## 一、总原则（违反任一条即返修）

1. **授权只针对产品功能，不针对开发过程。** 开发与测试仍然只用合成 fixture、隔离适配器、随机端口；Codex 不读真实 Vault、凭据、私人会话，不写真实 Agent 配置，不调用真实付费模型，不真跑夜巡。真实系统的第一次运行由用户本人在 5178 界面上触发，属于用户终验。
2. **四类授权能力的统一安全门**（每一类都要有，缺一类就算未完成）：
   - 默认关闭，用户在界面上显式开启，开启状态写入本机配置并可随时关闭；
   - 写之前预览：显示将写哪个文件、改什么（diff）、预计费用（如有）；用户确认后才写；
   - 写之前先备份，写之后回读核对；失败或结果未知时，先查询再决定，不盲目重试；提供一键回滚到备份；
   - 操作留痕：写入既有的操作日志，记录时间、对象、前后 SHA256、结果；
   - 凭据（API Key 等）只存 macOS 钥匙串，或由用户指定的本机环境变量提供；不写进 data/、仓库、日志、截图、前端响应。
3. **不编数据。** 能从本机数据算出来的就算出来；算不出来的继续写“待接入数据”，并在交接里说明原因。
4. **UI 沿用 STYLE-GUIDE 和 v14g**：控件 ≥ 44px；320/390 逐元素不越界、不裁切；axe 0 违规；减少动态效果时全部动画停止（含运行中切换）；不加换页特效或整屏闪光；不用 `--faint`；多选一用 radiogroup。新功能的入口按所在页的现有形式接入，不另起一套外壳。
5. **保护**：银饰页完全不动（源码、样式、截图逐像素对比）。资产仓库只新增功能入口，保持现有布局与风格；要放新区块时，按现有卡片和分区样式放在最下方或抽屉里，并在交接里附前后对比图。
6. 依赖：确需新增第三方依赖时，先在交接里写明用途、许可证、体积，**本单不预先授权安装**，能用 Node 内置或现有依赖实现的就不要加。
7. 测试断言不得放宽；因需求变化调整的断言逐条写进交接。

## 四、切片 2：四类授权能力（先写契约，再实现）

每一类都先写契约文档（放在仓库根目录，命名沿用现有 `*.md` 契约风格），写明：入口、开关、预览、写入范围、备份与回滚、失败与未知结果、留痕、费用上限、测试方式。契约写完直接实现，不用停下等批准；Claude 统一验收时一并审契约。

### 2-A 常驻 + 夜巡真实执行（`NIGHT-RUN.md`）
- **常驻**（路线 2.0）：用 macOS launchd 用户级 LaunchAgent 让工作台服务常驻，在设置里安装/卸载，并显示状态。安装前预览 plist 内容；卸载时完整移除。开发中只生成 plist 并测试内容，不真的 `launchctl load`。
- **夜巡 v1**：
  - 在夜巡窗口内，按草稿里的任务清单依次调用 Agent 的官方命令行非交互模式；
  - 首版只允许“只读 + 输出到指定目录”的任务，禁止 git push、删除和改写项目文件；
  - 每晚预算上限（来自草稿，硬性停止）、单任务超时、全局停止开关；
  - 每个任务的输出、退出码、耗时、费用估算写成运行回执；早上生成晨报，进待处理；
  - 任务清单结构化：在草稿编辑里逐条添加任务（目标项目、指令、允许的 Agent、输出位置）；
  - 表盘上显示真实执行时点和结果（成功/失败/跳过）；没有运行过就不显示。
- **成本用量**：按 Agent 汇总每晚费用（取命令行输出中的用量；拿不到时写“未知”，不估假数）。
- 测试：桩命令行模拟成功、失败、超时、超预算、停止开关；任何测试都不调用真实 Agent。

### 2-B 模型/API 真实连接（`MODEL-API.md`）
- 设置“模型连接”：选择提供方，填写 Key（存钥匙串），点“测试连接”时发一次最小请求；显示模型列表或错误；
- 学习成长“内容解析”（摘要/划线/问答）走这条连接：用户对单本书点击才执行，执行前显示预计输入量和费用上限，确认后执行；结果存本机，可删除；
- 每次调用记账到成本用量；
- 测试：HTTP 桩；Key 不出现在任何响应、日志和快照里（加断言）。

### 2-C 写真实 Agent 配置（`AGENT-CONFIG-WRITE.md`，扩展现有 AGENT-CONFIG.md）
- 智能体群内容清单的开关真实生效（启用/停用 Skill、插件）；发布挂载（把资产仓库里的 Skill 挂到指定 Agent）；
- 配置快照 + 跨 Agent 迁移（路线 4.4）：先选源和目标，预览映射与 diff，确认后写入；
- 会话级接力（路线 4.5）：只生成接力包，由用户复制到目标 Agent，不自动读私人会话；
- 每次写入：目录身份校验 → 预览 diff → 确认 → 备份 → 写 → 回读 → 留痕；一键回滚；
- 绝不写凭据相关文件（列入黑名单并测试）。

### 2-D 写入 Obsidian Vault（`VAULT-WRITE.md`，扩展现有 KNOWLEDGE-WRITEBACK.md）
- 随手记“写入 Obsidian”：写到用户在设置里指定的 Vault 子目录；默认新建文件，不覆盖；同名冲突时让用户选择；
- 个人说明修改建议“采纳”后写回 Vault（路线 3.3 未完成部分）：预览 diff → 确认 → 备份 → 写 → 回读；
- 只允许写指定目录（越界、符号链接测试）。

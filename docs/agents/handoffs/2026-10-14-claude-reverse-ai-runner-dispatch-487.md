## 一、可观察结果

软件标本的终端标题栏多一个执行器选择：点开是参照图那样的小菜单（真实图标 + 名称：**Codex**、**Claude Code**，外加一项 **仅 REA 取证 · 不用额度**，即 v4 现有行为）。默认 Codex，记住上次选择。选好后点“开始逆推”：

- 选 **仅 REA 取证**：与 v4 完全一致。
- 选 **Codex / Claude Code**：工作台以只读方式启动该 AI 的命令行，带上任务说明；它通过已注册的 `rea` MCP 取证分析。终端实时显示它的动作（调用了哪个 REA 工具、得到什么简短结果、它的阶段性说明），不显示原始大段输出。跑完后在任务包区出现：**结论**（每条标观察 / 推断，附证据编号）、**未知项**、**复刻任务包**（可复制、可存成 Skill）。

作品类不变（没有终端，直接出任务包）。

## 二、执行器约定

| 项 | Codex | Claude Code |
|---|---|---|
| 调用 | `codex exec`，JSON 事件输出 | `claude -p`，stream-json 输出 |
| 只读 | 沙箱只读、无需审批（不弹交互）；工作目录为本次运行的空临时目录 | 权限只放行 `mcp__rea__*` 与只读工具；禁用写文件、Bash 等；工作目录同上 |
| REA | 用该 AI 自己已注册的 `rea` MCP（setup 已写入两边配置）；工作台不另行注入 | 同左 |
| 额度 | 开始前在按钮旁显示“将使用 Codex 额度”；结束后若命令行给出用量（token / 费用），显示在终端末行 | 同左（“Claude 额度”） |

具体参数以两边当前版本实测为准，交接里列出最终命令行与实测输出样例；若某项只读限制在某个 CLI 里做不到，停下交回，不放宽。

## 三、任务说明与结果格式

1. 工作台按规则生成给 AI 的说明：目标（路径或网址、种类、SHA）、想弄懂、线索词；若本标本已有 v4 的 REA 取证结果，附上摘要和本机 `analysis.json` 路径，要求优先复用、不重复整包分析；网站目标附 CDP 端点与独立调试 Chrome 说明。
2. 要求 AI 最后只输出**一个 JSON 代码块**：`{ conclusions: [{ text, mark: "观察"|"推断", evidence: ["ev_…64位"] }], unknowns: [{ id, text }], pack: "复刻任务包全文" }`。工作台严格校验（字段白名单、长度上限、证据编号 64 位、无凭据），不猜补；解析失败时显示失败原因与终端末尾，可重试。
3. 解析成功后：结论与未知项存进记录；`pack` 经凭据过滤后成为这个标本的复刻任务包（覆盖前保留上一版，可切回）。AI 声称的“已验证”一律降为推断。

## 四、运行与边界

- 与 REA 取证、REA 更新共用“同一时间只跑一个”的锁；停止要结束整个进程组；总超时默认 30 分钟；服务重启时标“已中断”，不自动重跑；结果不明先查询，不重放。
- 终端日志沿用 v4 上限；原始事件流写入 `data/reverse-evidence/<记录>/<运行>/`，不进主库、不进导出。
- 命令行未登录、额度用尽、找不到可执行文件、REA MCP 未注册：分别给出可读提示（例如“请先在 Codex 里登录”），不自动修复。
- 不读取或修改 AI 的会话记录与配置；不传入工作台数据目录以外的路径（目标路径与 analysis.json 除外）；不在说明里放任何凭据。

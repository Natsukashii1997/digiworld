## 1. 改了什么

- 服务端 `server/project-status.mjs`：
  - `parseCurrentOutline(text)`：按“新内容写在最上面”的约定，取第一个 `## ` 二级标题与它下面第一段正文作“最近进展”。跳过代码块（含代码块里的假标题）与表格行，列表 / 引用去掉标记，链接只留文字，去掉强调；标题上限 120 字、正文 300 字，超出加“…”。
  - `withOutline(parsed, text)`：只有状态表解析结果为 `unparsed` 且找得到二级标题时，状态改为 **`outline`**，带 `outline:{title, summary}`；`fields` 仍为空。有任何状态表字段（ok / partial）照旧；没有二级标题仍是 `unparsed`。
  - 项目状态卡（`/project-status/inspect`）与协作板（`server/collab-board.mjs` 的 `boardItem`）共用。阶段推断只认 ok / partial，所以 outline 的阶段是“未知”，持笔者未知。
- 口令 `src/collab.js`：`statusOf` 带 `outline`；`startPrompt(item, agent, { next })` 在 outline 时写“最近进展（CURRENT.md 最上面一节）：标题 + 首段”与“下一步（用户在工作台手填）：…”（未填则“未填写（读完最近进展后先向用户确认）”），开工规则改为“按项目自己的 AGENTS.md 约定认领与交接”，不写“唯一下一步”与写入者规则。有状态表的项目口令不变，手填下一步不进口令。
- `src/relay-desk.js`：`relayDesk` 多返回 `next`（项目桌手填下一步）；`src/projects-v16.js`：`projectRelayPrompt` 把它传给 `startPrompt`；新增 `continuableCurrent`（ok / partial / outline 可继续），`readableCurrent` 不变（写入者、阶段、停滞、活动热度仍只在 ok / partial 时显示）。
- `src/project-freshness.js`：发车签名加入 `current.outline`，最近进展变化即要求重新继续并预览。
- `src/ProjectsV16.jsx`：
  - 存档卡在 outline 时：NEXT 区显示手填下一步（`ManualNext`），主区下方加 “RECENT · 最近进展”；「继续」可用；阶段条提示“没有协作状态表，阶段不推断”。
  - 继续、复制前的可读检查改用 `continuableCurrent`。
  - 发车条把手填下一步并入“项目桌变化”判断：预览后下一步变化即要求重新预览；复制前重读工作台核对，不一致提示“收件、装备或下一步已变化，请重新预览口令。”。
- `src/ProjectDesk.jsx`：`deskRows` 多返回 `next`；新组件 `ManualNext`（写 / 改下一步，单行，≤500 字）。保存走 `settleAttempt("retry")`：先查询，已是目标即完成；别处改过（与开始编辑时的文字不同）记为冲突，不覆盖、提示并采纳最新内容。服务端 `POST /project-desk/next` 本身也按 `base` 拒绝覆盖（A 批）。
- `src/ProjectStatus.jsx`：详情抽屉对 outline 显示“没有协作状态表 · 最近进展”和说明；读取完成的动效不把 outline 当“完整可读”。
- `src/projects-v16.css`：`.pj-recent`、`.pj-next-empty`、`.pj-next-edit`、`.pj-next-form`、`.pj-next-act`，只用令牌。

## 重要：优先处理的日常路径

### F01 未提交输入会随切页消失

**证据等级：代码确定；未在真实界面写入测试内容。**

首页的文字和未知保存 attempt 只在 `HomeV16.jsx:126–127` 的组件内存中。网页随手记的 draft/newDraft/failure 也只在 `NotesV16.jsx:39–41` 中；新建时没有离开保存回调（102）。主导航直接换路由（`App.jsx:248–257`），页面按 route 卸载（435、438、458），无上层草稿或离开保护。

触发：写了一半新便签，切到其他板块再回来，输入丢失。保存结果未知时离开，还会丢掉原操作 ID 的查询线索。类似缺口存在于资产交付目标编辑：`AgentTargets.jsx:30–46` 的 pending 只传给 Settings 内部，`SettingsV16.jsx:145、301` 只拦设置分类/Agent 切换，不拦主导航。

最小修复：持久保存草稿及原操作 ID；返回后恢复，未知保存先查询；设置目标至少保留草稿或明确确认放弃。不要把切页变成隐式正式提交。验收包含切页、刷新、关闭重开、断连后恢复、中文输入中途离开。

### F02 随手记一种异常身份会让“重试”持续无效

**证据等级：当前代码纯内存合成复现，根代理独立复核。**

`src/api.js:23–35` 缓存成功 HTTP 响应，即使身份为 null；`floating-notes-store.js:23` 在请求 notes 前拒绝该身份。模拟首次 session 身份缺失、下一次已恢复，init 加两次 refresh 的结果仍为：session 请求 1 次、notes 请求 0 次、online=false、ready=false。错误还会被悬浮栏的通用“未启动”提示掩盖。

最小修复：尚未绑定有效身份时，显式重试应重新获取会话；显示可区分的失败原因。必须保留真实目录切换和待决草稿的保护，不能以放宽身份检查来修复。该发现是独立残留路径，不说明 599 的修复无效，也不证明当前正式窗口仍处于此故障。

### F03 便签标题搜不到，命中后也不直达便签

**证据等级：标题遗漏纯内存复现；跳转行为代码确定。**

`src/search.js:107–109` 只搜索正文、不搜索 title。用合成便签“标题=独有标题词，正文=普通正文”验证：查标题 0 条，查正文 1 条。`App.jsx:700–705` 结果仍以正文片段为标题，点击只去随手记板块，没有携带记录 ID。

最小修复：索引并显示实际标题；结果点击定位目标卡片。验收三类便签、仅标题有内容、正文命中和同名记录。收藏、焚决及现行逆向记录的跨板块检索属于后续功能扩展，不能悄悄把 Vault 或私人会话加入搜索范围。

### F04 收藏已恢复连接，仍显示旧错误

**证据等级：当前函数纯内存合成回放；根代理逐行核对。**

`src/collection/app/page.tsx:19–29` 先比版本，相同即返回，跳过清除读取错误。正常加载→短暂断连→恢复且版本未变时，错误仍留在状态中，`DeskView.tsx:1443` 持续展示。

最小修复：同版本健康读回也清除读取故障；把读取错误和未知写入结果分开，避免清掉尚未核对的导入。

### F05 收藏导入结果未知，被说成“没有收录成功”

**证据等级：代码确定；未做真实故障注入。**

`xhs-client.ts:52–68` 已有 operationId 及查询，明确可能抛出“结果待核对”或“收藏已保存，返回结果不完整”；`DeskView.tsx:987–997` 却统一显示“没有收录成功”，反馈 3.6 秒后消失。

触发：后端已保存但响应丢失，或保存成功后 notes/布局回读失败。用户容易误判并重复导入。

最小修复：区分明确失败、结果未知、已保存待回读；保留操作 ID 和查询入口，先核对原次结果再决定是否重试，不要求用户抄编号排错。

### F06 项目“当前状态”可能是旧快照

**证据等级：代码确定；未扫描真实项目或执行接手。**

`App.jsx:137–172` 只在在推进项目 ID 集合或停滞阈值变化时刷新。重新绑定路径、重新扫描、外部 CURRENT 更新、返回页面都不触发该缓存刷新。`ProjectsV16.jsx:314–318` 又只与同一缓存判断 stale。

影响：继续项目时可能复制旧目录或旧下一步。口令要求 Agent 再读 CURRENT 能降低误执行风险，但页面的事实仍可能过期。

最小修复：绑定/扫描变化使缓存失效；点击继续前重新核对目标项目，显示最后读取时间。保持 CURRENT 为事实源，不维护另一份项目进度。

## 重要：低频但应补齐的可靠性边界

### F07 可以生成当前页面无法恢复的完整备份

**证据等级：代码确定，容量边界算式已核对；未生成/恢复真实备份。**

`server/full-backup.mjs:14` 允许打包 1 GiB 的源文件总量，生成端未限制对应 ZIP；`src/StoragePanel.jsx:303–305` 拒绝超过 75 MiB 的 ZIP，并让用户“在本机直接处理”，没有在此提供可操作的恢复路径。恰好 75 MiB 的文件经过 Base64 和 JSON 包装，也比 `server/http.mjs:101` 的 100 MiB 限额多 25 字节。

最小修复：对齐生成、上传、恢复的容量契约；大包提供可直接使用的本机恢复入口。验收用隔离资料完成包含图片、历史记录和近上限包的完整往返，不只验证下载成功。

### F08 恢复完成但回包丢失后，无原次结果查询

**证据等级：代码确定。**

`full-backup.mjs:304–309` 在恢复前消费内存 token，没有持久操作回执；`StoragePanel.jsx:376–381` 失败后只显示错误。若新目录已生成而回包丢失，同 token 重试报失效，重新预览又可能恢复另一目录。

原库不会因此被覆盖，但用户无法可靠知道第一次是否完成。最小修复：稳定操作 ID、目标目录与持久结果；未知时核对原次结果，界面不直接重做。

### F09 两个窗口保存扫描目录可能静默互相覆盖

**证据等级：代码确定；未修改真实扫描配置。**

`ProjectSettings.jsx:120–126` 未携带草稿起点 revision/指纹；`server/http.mjs:949、960–963` 仅防扫描进行期间发生变化。A、B 同时打开设置，B 先保存新配置、A 后提交旧草稿时，服务器把 A 当作新的有效设置，覆盖 B。

最小修复：保存新范围携带起点指纹，冲突保留输入；只刷新扫描时使用服务器最新范围。验收两个隔离客户端串行保存和扫描中并发变更。

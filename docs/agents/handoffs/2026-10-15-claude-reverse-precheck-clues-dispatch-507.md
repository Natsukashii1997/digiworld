## 一、网站目标免费预检（不调用 AI）

**可观察结果**：网站标本点“开始逆推”（任一执行器）时，工作台先用 REA 列出调试 Chrome 中同源的页面：

- **恰好一个页面与标本网址完全一致** → 直接开跑，行为同现在。
- **没有完全一致的页面** → 不启动 AI，终端标题栏下方出现提示：“调试 Chrome 当前打开的是：`/agents`（标题：炉子）……与目标 `/community` 不一致”，并列出同源已打开页面（最多 10 个，显示路径 + 标题）。每个页面一个按钮“改用这个页面”：点了即把标本网址改为该页面并立刻开跑（同一次点击里用户已明确选择，不再二次确认）。另给一个“我去 Chrome 里切到目标页”的提示，用户切好后再点“开始逆推”。
- **多个页面完全一致** → 提示“只保留一个该网址的标签页”。
- **连不上 9222 / 没有同源页面** → 沿用现有独立调试 Chrome 指引与命令复制。

实现要点：

1. 复用现有 `list-browser-targets` 调用与 `browserTargets` 解析（`server/reverse-runner.mjs` 网站分支），抽成可单独调用的预检；只读、不花额度，超时 15 秒。
2. 改网址走现有参照物修改路径（revision 校验、写后回读）；改网址后旧的达标 / 任务包规则按现有“目标变化”逻辑处理。
3. 同样的预检也用于“仅 REA 取证”。Electron 目标不受影响。
4. 不导航、不新开标签、不读页面内容；页面标题与 URL 仅用于提示，过凭据过滤（URL 中的 userinfo 已由 REA 去除）。

## 二、AI 顺带解析线索词

**可观察结果**：录入抽屉里的“线索词”改为可选，提示改成“可不填；AI 会根据‘想弄懂’自动定线索词”。用 Codex / Claude Code 逆推时：

1. 提示词要求 AI **先**根据“想弄懂”（和用户填写的线索词，如有）定 3–8 个英文线索词，用于 `trace_application_feature`（Electron）或在网站脚本证据中检索；并在终端以一行可读文字先报告：“线索词：migrate、handoff、context …”。
2. 结果 JSON 增加可选字段 `clues: string[]`（最多 8 个，每个 1–60 字符，ASCII 字母数字及 `._:/-` 等常见符号，去重；严格校验，非法即整个结果按现有规则拒收）。
3. 结果区在“结论”上方显示一行“AI 用到的线索词”（小字标签样式）；每个线索词旁有“加入标本”，点了写入该标本的线索词，供下次“仅 REA 取证”或再次逆推复用。用户自己填过的线索词与 AI 补充的分开标注。
4. 不新增任何单独的 AI 调用。“仅 REA 取证”仍只用用户已填线索词；未填时保持现有“只做整体解析”提示，并加一句“用 AI 逆推可自动定线索词”。

## 三、测试

- 单元：预检四种分支（唯一匹配 / 不匹配并列出候选 / 多个匹配 / 端点不可用）用假 REA；“改用这个页面”的 revision 冲突与写后回读；`clues` 字段校验（缺省、超长、非法字符、超过 8 个、重复）；旧结果无 `clues` 兼容。
- 浏览器：1440 / 390 / 320 不匹配提示与候选按钮（44px、键盘、焦点）、线索词标签与“加入标本”。

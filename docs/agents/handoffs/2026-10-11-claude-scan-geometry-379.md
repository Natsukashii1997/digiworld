# Claude｜扫描线与内容显现不同步 · WB-20261011-379

输入状态：WB-20261011-378（写入者无）。常浩：“夜巡，日历，随手记存档点，都是错的”。认领379直接修。

## 根因（378 及之前都没测到）

此前所有检查都只数 `.scan-surface` 有几个，从未比较“线走到哪”和“内容显现到哪”。切页扫描在切页瞬间读取主区高度并固定下来，青线按这个高度走；内容显现 `clip-path: inset(0 0 100% 0)→inset(0)` 却按**实时**高度走。这几页切页瞬间内容尚未渲染完，之后才长高（随手记相反，先高后矮）：

| 页面 | 切页瞬间高度（线走的距离） | 稳定后高度（显现边缘） |
|---|---|---|
| 夜巡 | 405 | 1259 |
| 日历 | 263 | 1126 |
| 存档点 | 422 | 1043 |
| 随手记 | 1978 | 800 |
| 资产仓库、协同 | 一致 | 一致 |

结果是一道青线和一道显现边缘以不同速度下移，看起来就是两道线；夜巡、日历、存档点的线还停在屏幕中上部。与常浩点名的四页完全对应。

## 改动（`src/scan-motion.js`，约3行）

- 扫描高度 `h`：切页 = 主区顶部到屏幕底部（固定扫满可见屏幕，不看瞬间内容高度）；其他时刻 = `min(目标高度, 屏幕内可见高度)`。
- 青线与拖尾 `translateY(h)`；内容显现改为从顶部按像素裁剪 `polygon(0 0,100% 0,100% 0px,0 0px)→…${h}px…`，与线同时长、同缓动，二者始终同一位置；后长出的内容在屏内同样被这道线扫出。
- 378 的“页面自己读取不补线”规则保留。

## 一句话结果

在别的应用里按 ⌃⌥N 或点桌面上的小圆球，就能直接写中文便签；收起、退出重开都不丢；写下的内容会出现在数码世界随手记页，两边改同一条时不会互相覆盖。

## 一、范围与分批

三批可以在一次认领内连续完成，但每批单独交接，便于 Claude 分批复核。批 1、批 2 改的是共享面（服务路由、前端公共页、测试入口），按 COLLABORATION 串行写入。

### 批 1 · 单条便签写入与跨端刷新（服务端 + 网页端）

**可观察结果**：便签栏不再整库提交；两个窗口改同一条时能发现冲突；网页随手记页能看到便签栏写入的新内容。

1. 新增有限的便签写接口，只能新建或修改**一条**便签，复用现有事务、串行落盘、原子切换指针、写后回读和鉴权，不放宽同源边界。不提供删除。
2. **幂等新建**：客户端生成固定 id；重放同一 id 且正文相同即视为成功，不重复新增；同 id 不同正文按冲突处理。
3. **单条冲突检测，不改 schema**：现有 note 字段严格为 `id/text/at/format/refined`。请求携带客户端编辑起点的正文（或其摘要）作为基准；服务端发现当前正文与基准不同即返回冲突和当前版本，不写入。`at` 的含义沿用随手记页现有语义，不新增字段；如认为必须改 schema，先停下交回 Claude 说明理由。
4. “结果未知”（超时、回包丢失）：先按 id 查询核对，再决定是否重发，不盲目重放。
5. 网页端：窗口重新获得焦点时和每次整库提交前核对 revision；过期就刷新，不能让便签栏的写入导致网页下一次保存时整库冲突失败。随手记页正在编辑的那一条不能因为刷新而丢字（保留草稿，按冲突处理）。
6. 校验沿用现有规则：`md1`、NOTE_MAX、控制字符、id 格式。

### 批 2 · 便签栏页面（复用现有编辑器）

**可观察结果**：一个独立的便签栏页面（例如 `/#/float`），368 宽时与 FN-516 v1 的 §03 九种状态逐一对得上。

1. 组件与令牌严格按设计说明 §5 规格表：栏头 52、新建条 56、便签卡（沿用 `notes-v16` 纸色/胶带/字色，窄栏不倾斜）、编辑中暖黄、卡底工具条（随手记 390 版：无序/有序/待办 | A▾，右侧显示保存状态，无“贴上”）、栏底状态行 44、失败条、冲突条。共用部分抽成共享组件或复用现有组件，不在页面里深度覆盖样式。
2. 编辑器**复用 `NoteEditor` 及 `note-document`**（中文输入法、列表、待办、字色）。不要沿用视觉稿里的 contenteditable 演示代码。
3. 自动保存：每次停手约 0.3 秒写本机恢复区；停手约 1 秒或收起前送入批 1 的接口。空白新便签不保存。⌘N 新建、Esc 收起、⌘↵ 写完这条、↑↓ 在便签间移动焦点。
4. 恢复区只放草稿和待提交操作，不成为第二份便签库：有界、按便签 id 记录、确认已保存并回读后才清除；退出重开能恢复。存放位置由你决定（宿主 Application Support 经桥接，或持久化的网页存储），交接里写明理由。
5. 状态文案以设计说明 §5 第二张表为准：已保存、保存中、草稿待保存、保存失败、结果未知（正在核对是否已保存…）、同条冲突（“两条都留”为主按钮，“用别处的”为次按钮；选择前收起工具条）。界面不出现接口、版本号等技术词。
6. 栏底“在数码世界打开”打开随手记页。栏内不放复制、炼入、删除。
7. **设计未画的一个状态**：打开时数码世界服务未运行。用已批准组件拼出：空状态布局 + 一句“数码世界还没有启动，写过的草稿都在本机” + 重试；连上后自动恢复草稿。交接里单独截图，Claude 在 T2 判断。

### 批 3 · 轻量 Mac 宿主

**可观察结果**：一个本地构建出来的小程序，桌面上出现悬浮球，点开即批 2 的便签栏。

1. 建议 AppKit + `NSPanel` + `WKWebView` 加载工作台同源的便签栏页面（`http://127.0.0.1:5178/`），不引入整套跨平台运行时。代码放新目录（例如 `desktop/floating-notes/`），用本机已有 Swift 工具构建；如需 Xcode 工程或任何第三方依赖，先停下说明。
2. 悬浮球：直径 52pt、命中区 60pt、离屏幕边 12pt；造型照视觉稿（深墨蓝圆盘、暖黄内环、胶带、`mark_pencil` 像素铅笔按原网格绘制，不生图）。点它不让当前应用失去输入焦点；展开后便签栏才接收键盘输入。状态点、保存弧线从页面状态桥接过来。
3. 拖动：移动超过 4pt 才算拖动；离边 48pt 内出现贴边线；松手吸到最近的左/右边，上下保留；按显示器分别记住位置；显示器或分辨率变化后挪回可见区域。
4. 便签栏：368pt 宽，高 = min(600, 可用高 − 24)，离球 12pt，总往屏幕内侧展开；按 `visibleFrame` 计算，不压菜单栏和程序坞。栏头可拖动面板，但不改球的位置记忆。
5. 失焦：默认点外面收起，收起前先把草稿落到恢复区；钉住后不收起。**中文输入法候选窗、系统拼写面板不算失焦**，这一点必须实测。
6. 层级：球和栏浮在普通窗口之上，所有桌面空间可见；全屏应用中默认隐藏球，⌃⌥N 仍可呼出栏。
7. 全局快捷键 ⌃⌥N（使用不需要辅助功能权限的注册方式），可在宿主设置里改；与系统或常用应用冲突时提示，不静默失败。
8. 只在项目目录内构建和运行验证。**不安装到“应用程序”、不加登录项、不改系统设置、不替换现有“数码世界.app”**；这些属于采用步骤，要常浩另行授权。

## 二、不变量（不能为简化而去掉）

- 正式便签只有主库 `state.notes` 一处；恢复区不是第二份库。
- “已保存”只在主库写入并回读成功后显示。
- 冲突时两边内容都保留，选择之前谁也不覆盖谁；“两条都留”把自己的版本存成新的一条。
- 回包不明先核对，不重复新增。
- 不读取真实便签正文做测试；使用合成数据和隔离的 data 目录。

## 三、测试与证据

- 单元：接口的新建、修改、幂等重放、同 id 不同正文、基准不符冲突、未知结果核对、校验失败；网页端 revision 过期刷新且不丢正在编辑的内容。
- 浏览器：便签栏页面 368×600 下九种状态 + “服务未启动”；中文长文、空白、键盘（⌘N/Esc/⌘↵/↑↓）、44px 命中区、焦点可见；自动保存 0.3/1 秒节奏；退出重开恢复草稿；两窗口同改一条出现冲突且“两条都留”生效；网页随手记页能看到便签栏的新内容。
- 宿主（真机实测并保留录屏或截图）：在另一应用前台时用 ⌃⌥N 和点球唤出并输入中文；拖动吸边与位置恢复；左/右/上/下靠边时的展开方向；失焦收起与钉住；输入法候选窗不触发收起；全屏应用中球隐藏；多显示器（如具备）。
- 视觉：每批交接附与 FN-516 v1 同状态的前后对照图（便签栏 368 宽、球 1:1 与 2:1）。
- 全量回归按项目惯例运行；未执行的检查写明原因。

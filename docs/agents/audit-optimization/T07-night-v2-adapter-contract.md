# T07 夜巡 v2 生产适配接入合同（候选）

当前 `server/night-v2-harness.mjs` 只接受 `executionMode: 'synthetic'`，`server/http.mjs` 生产默认 `disabled`，没有启动调度器。本候选仅把“何时能接生产适配器”变成可核验接口；**不启用真实夜巡**。

## 独立授权与绑定

每个锁定槽必须有当次 `night-v2` 授权回执：`runId`、夜晚日期、计划 SHA、槽 ID、项目 ID、目标 ID、worktree 身份、分钟与轮次预算、到期时间；不能复用 v1 夜巡、Agent 写门或 T06 授权。目标发现与授权回执必须逐字段回显并匹配同一预算。每次启动新轮次前重查回执、目标能力与 worktree 身份，变化即停止。授权不能由计划中的 `approved` 字段替代。

适配器的只读 `discover` 必须证明目标可识别、可硬限制时间与轮次、可停止、可查询原进程、可回收产物、在独立 worktree 运行；`inspectNightV2Adapter` 只校验注入回执结构，不证明该声明真实。实际 CLI 非交互命令、预算参数、退出语义与输出协议须用官方资料和隔离试验核实后才实现。

## 与现有夜巡 harness 的接线点

1. 开工检查的 `executor` 项调用目标 `discover`，并将身份与锁定计划一起记录；没有完整证据则 `failed`。
2. `executeRound` 接收并核对 `runId`、`planHash`、`slotId`、目标及 worktree 身份、时间/轮次/额度预算，运行前写持久轮次，再调用真实适配器。当前 harness 尚未向 `executeRound` 传完整 `planHash` 与 worktree 身份，接线前必须补齐。
3. `stop` 发信号后通过 `probeProcess` 回读；不因发信号就标已停。重启后先查询原进程与最后绿提交，未知时不重放。
4. `readArtifact` 只能读取受控 worktree 中本轮登记的产物，验证 SHA、大小、来源与类型，再进入晨报；读取失败保留未知。人类晨间合并/派白天/续跑/丢弃仍走现有 `night-v2-actions`，不自动执行。

## 当前仍缺的工程与真实验收

- 目标 CLI 的非交互执行、停止、原进程查询、硬预算和产物协议尚无事实验证；不能凭空填命令。
- 23:00–07:00 执行窗口、06:30 后不开新任务，以及 22:00 预告、22:55 开工检查、07:05 晨报通知均未接生产调度；系统级常驻、防休眠、重启恢复及多槽联动也未接生产。本候选不把合成 ledger 当生产就绪。
- 首次真实夜巡仍需用户为具体项目、任务、预算、红线与本晚计划单独授权，再做目标环境试跑和次晨逐槽验收。

## 实现约束与独立验证

1. 插件保留既有配对与来源校验，只把白名单模式交给本机。密钥、GET 请求均由本机后端处理，不放扩展、不读取网站 Cookie。
2. 持久化 GET 任务：本地操作、作品 ID、卡片生命周期、远端 task/note ID、状态、查询时间和非秘密配置标识。先落请求意图，收到任务编号后立即落盘。重启续查已有任务；未知提交进入待核对，不自动重建。官方CLI当前源码新增 `client_request_id` 幂等字段，生产设计应固定并验证其行为；不能追溯保护此次未携带该字段的小红书未知请求。
3. 原收藏和 GET 结果独立。GET 失败不丢原收藏。重复点击、普通收藏后补 GET、重导入应复用解析/任务；重复导入不能抹掉已有 GET 字段或重复触发费用。
4. GET 回填使用当前串行读改写，避免覆盖分组。删后不复活；删后重收藏同作品时，旧任务不能误挂新卡片。来源去重键与实际提交 URL 分离。
5. GET 结果早于本地媒体完成时，结果留在持久任务内，待相应生命周期的卡片写入后挂接。若采用先收藏后排队 GET 的较简单方案，须明确实际等待体验。
6. Tab 沿用现有阅读器、连续下拉和焦点标准，显示申请/处理中/完成/失败/待核对。保存 GET 原始生成正文快照与来源、时间，不额外改写，不做双向编辑同步。安全渲染，不能注入返回 HTML。
7. 搜索索引加入 GET 标题/正文，命中标识 `getAnalysis`；MCP 全文读取携带来源、时间和状态，不将 AI 整理标成作者原话。

适配位置：扩展 content/background；后端 collection 与独立 GET 适配/任务模块；xiaohongshu 类型、DeskView；note-search 与 collection-mcp。现有版本 `1.1.0` 尚未修改。

关键回归：双击/重导入、断电后续查、提交响应丢失、GET 权限/额度失败、删除/删后重收藏、分组并发、完整内容保存与搜索/MCP、原直接收藏不变。UI 按既有数码世界方向，根代理负责实现及证据，Claude 质量验收及常浩真人验收分列；不重塑整个页面。

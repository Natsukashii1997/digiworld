## 3. 推进节奏

每个切片固定走：

**契约 → 隔离实现 → 全量回归 → 交接 → 另一方独立复核 → 用户真实使用验收**

- **硬规则**：上一个切片没通过用户真实使用验收，就不开下一个大切片。纯工程类小切片（如测试、收口）不受此限。
- **例外（用户 2026-09-29 决定）**：第一阶段内 1.2 推迟到阶段末，顺序改为 1.1 → 1.3 → 1.4 → **第一阶段整体验收**（覆盖 1.1 使用记录、1.3 搜索与真实复用）。整体验收通过前不进入第二阶段。
- 凡是涉及真实 Vault、真实 Agent 配置、付费模型、飞书或外部账户的步骤，先停下来请用户单独授权。
- 回归基线：`npm test`、全部浏览器 / axe / 迁移脚本、`tests/visual.mjs`。每批交接都记录结果和代码指纹。

## 4. Claude × Codex 分工

协议不变，见 [COLLABORATION.md](COLLABORATION.md)：同一时间只有一方写入，另一方可以只读复核，通过 CURRENT 和交接文档交接。

| 角色 | Codex | Claude |
|---|---|---|
| 主导实现 | 后端与 Agent 集成（尤其 4.1 单目标执行要真正调用 Codex）、它原先编写的领域模块 | 前端与交互、跨模块重构、测试设计 |
| 独立复核 | 复核 Claude 的改动 | 复核 Codex 的改动（产品规则、权限边界、证据分层） |
| 文档 | 切片契约 | PRD、路线图 |

- 一个切片由一方实现、另一方复核。只有文件完全不重叠，且事先在 CURRENT 中登记了各自的文件范围时，才允许两边同时开工。
- 两边之间没有自动通知，需要用户传一句话，例如“读 CURRENT 继续”。
- 额度与效果（如实说明）：把实现交给 Codex，会减少 Claude 这边的消耗；但复核和读交接仍会消耗，总成本不一定下降。交叉复核能提升质量；需要长时间连续推敲的设计工作，由一方连续完成效果更好。长对话每一步的成本都在上升，建议每个阶段开新会话，从 CURRENT 接续。

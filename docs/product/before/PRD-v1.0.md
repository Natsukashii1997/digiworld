## 1. 一句话定义

**一个跑在你这台 Mac 上的“个人 AI 能力管理层”：把散落在各个 Agent、会话和文件夹里的 Skill、Prompt、工作流、项目上下文和知识，变成可积累、可找回、可复用、可迁移的个人 AI 体系。**

它**不是**又一个聊天窗口。日常干活仍在 Codex、Hermes、Claude 等原生 Agent 里完成。工作台负责让能力找得到、版本说得清、交付可核验、项目可接续、失败可恢复。

## 2. 要解决的问题

| 痛点 | 今天的真实表现 | 工作台要带来的改变 |
|---|---|---|
| 能力分散 | 好用的 Prompt 找不到；Skill 不知道存在哪、装给了谁 | 统一收录、搜索、版本化，一键复制给任意 Agent |
| 换 Agent 就断 | 换会话或换 Agent 要重新解释项目背景 | 项目 Current 指针加交接包，新 Agent 能按同一规则接手 |
| Agent 难管 | 配置出错要逐个排查，不知道装了哪些版本 | 自动发现、明确管理目标、受控改配置、可恢复 |
| 知识不连续 | 资料收藏了但没有综合，旧结论不会随新证据更新 | 连接 Obsidian，形成“整理 → 候选 → 保存 → 来源变化复核”的链条 |
| 执行不可持续 | 夜间和长任务无法无人值守 | 受控的单目标执行，再扩展到夜间队列和编排（远期） |

**检验标准**：已有能力能否被稳定复用、管理和延续，而不是首页有多少入口。

## 3. 用户与使用场景

**唯一用户**：你本人，单机单人使用，同时使用多个 AI Agent（Codex、Hermes、Claude 等），有 Obsidian 知识库，也有多个本地和 GitHub 项目。首版不考虑团队、跨设备和移动端。

**三个检验核心价值的场景**（决定首期成败）：

1. **Skill 跨 Agent 复用**：收录一个好 Skill → 打开详情 → 复制安装口令 → 粘贴给任意 Agent → 目标安装并使用。系统必须区分“已收录 / 口令已复制 / 目标已安装 / 使用已验证”。
2. **成熟做法变成流程资产**：自己写一套流程（目标、输入、步骤、检查点、输出），引用已有 Prompt/Skill 的固定版本，保存、迭代，再完整复制给 Agent。
3. **换 Agent 继续同一个项目**：选项目 → 生成交接包（Current 指针 + 规则 + 哈希）→ 新 Agent 能复述目标、最新纠正、成果位置、权限和下一步。

**贯穿主线**：收集或创建 → 整理并保留来源 → 找到可用版本 → 选择目标 → 复制、分发或执行 → 在目标环境使用 → 回收结果 → 更新资产。不要求每次都走完整条链。

## 4. 已确认的产品原则（不可违背）

| # | 原则 | 含义 |
|---|---|---|
| P1 | 优先级 **资产复用 ＞ Agent 管理 ＞ 项目与知识连续性 ＞ 持续执行** | 资源投入按此顺序；低优先级模块不得反客为主 |
| P2 | 混合归属，原件不搬家 | Skill/Prompt/流程由工作台管理；知识留在 Obsidian、项目状态留在各项目 Current、Agent 配置留在原位 |
| P3 | 证据分层，不把前一层说成后一层 | 检测到程序 ≠ 确认目标 ≠ 配置已写 ≠ 进程已采用 ≠ 真实任务有效；复制 ≠ 安装 ≠ 使用 |
| P4 | 受控写入 | 预览固定版本 → 明确确认 → 再核验 → 写入 → 回读；结果未知先查询，不盲目重试 |
| P5 | 历史不可变 | 恢复 = 新增版本；来源更新不覆盖个人改版 |
| P6 | 本机优先、隐私优先 | 只监听 127.0.0.1；不读凭据和私人会话；Skill 交付仅限本机 |
| P7 | 重要判断交给人 | 系统可以发现、整理、建议；采纳正式知识、覆盖配置等由用户确认 |
| P8 | 诚实状态 | 扫描失败、未授权、未覆盖不得显示为“无内容”“健康”或“已完成” |

## 5. 信息架构

### 5.1 页面结构（当前 9 个页面，hash 路由）

```
工作空间
├─ 资产库 #assets        Skill / Prompt / 工作流 的卡片库 + 详情抽屉 + 新建/编辑
├─ Agent 中心 #agents    发现 → 管理目标 → 目录与资产 → 配置管理 → 上下文接力
├─ 项目空间 #projects    本地/GitHub 发现 → 身份与目录 → 项目上下文 → 交接包
├─ 知识连接 #knowledge   连接 → 扫描/查询 → 整理任务 → 候选保存 → 来源维护
├─ 随手记 #notes         本地草稿
└─ 夜间模式 #night       计划草稿
探索与管理
├─ 拆解与参考 #references 链接 + 笔记
├─ 版本与归档 #history    资产版本修改记录、归档资产
└─ 模型与设置 #settings   模型意向草稿、本地数据导入导出、移除示例
全局：⌘K 搜索（仅资产标题 + 页面名）、快速记录按钮、保存状态指示
```

### 5.2 核心对象模型

| 对象 | 权威位置 | 工作台保存什么 |
|---|---|---|
| 资产 Asset（skill / prompt / workflow） | 工作台主库 | 身份、类型、全部版本（不可变）、来源、标签、收藏/归档、Skill 完整包 |
| 工作流引用 | 工作台主库 | 固定到 Skill/Prompt 的某个版本，最多 50 条，不嵌套 |
| Agent 发现记录 / 管理目标 | 发现来自本机扫描；目标由用户确认 | 程序入口、版本证据、Home/Profile 组合、已关联 Skill 副本 |
| Agent 配置操作 | Agent 原生配置文件 | 仅操作记录与恢复日志（`data/config-operations/`） |
| 项目 Project | 项目目录、GitHub、项目 Current | 稳定 ID、目录/远端映射、Current 与规则的**指针** |
| 知识连接 / 整理任务 / 候选 | Obsidian 原文 | 来源指针、任务 manifest、候选正文、写入恢复日志（`data/knowledge-writes/`） |
| 随手记 / 参考 / 夜间 / 模型 | 当前仅工作台主库 | 草稿 |

存储方式：`data/CURRENT.json` 指向不可变 JSON 快照，带 revision 和 SHA256，写入原子替换后回读。SQLite 只用作进程排他锁。

## 6. 功能需求与现状

图例：✅ 已实现且本地验证　◐ 部分或仅草稿　○ 未开始　👤 待真人验收（目前全部模块都在这一状态）

### 6.1 资产库 · Skill 公用池（R01，最高优先级）

**目标**：一个 Skill 收录一次，所有 Agent 都能复用；版本、来源、个人改版清清楚楚。

| 功能 | 状态 | 说明 |
|---|---|---|
| 完整 ZIP 导入（10 MiB / 展开 25 MiB / 300 项，拒绝路径逃逸） | ✅ | 结构校验不等于安全准入 |
| 本机 Skill 发现 → 预览完整包 → 确认收录 | ✅ | 限定扫描根，不做整盘扫描 |
| 固定来源与独立个人改版 | ✅ | 来源更新不会覆盖改版 |
| 复制本机安装口令（10 分钟临时 ZIP 链接，可撤销） | ✅ | 仅限本机；服务重启后链接失效 |
| 导出完整包 | ✅ | |
| 目标副本：查找已装副本 → 与固定版本逐文件比较 → 关联 | ✅ | 只读核对，不覆盖、不同步 |

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 只监听 loopback；校验 Host/Origin/Token；请求体、路径、符号链接、硬链接、稳定字节逐层检查；包链接只授权单个 ZIP |
| 可靠 | revision 冲突拒绝；写后回读；结果未知时持有操作 ID 查询；损坏时拒绝使用，不静默回退 |
| 隐私 | 不读凭据、Token、私人会话；知识正文不全库复制；`data/` 不进 Git |
| 性能 | 当前没有测量数据。优化前先测包体积（JS 415 KB / gzip 128 KB）、长列表、diff 和扫描耗时 |
| 可访问性 | 键盘可达、焦点管理、axe 无违规（历次 QA 覆盖） |
| 兼容 | 旧 IndexedDB 数据迁移入口保留；schema 变更必须带兼容与恢复测试 |

## 8. 遗漏与问题诊断（Claude 分析，待确认）

按对核心价值的影响排序：

### 8.1 最大风险：功能在加，真人验收为零

v0.4 到 v0.17 共十几个切片，全部停在“本地验证通过、待真人使用”。首版验收 **S07（真实 Prompt、Skill、流程走完从收录到在 Agent 里使用）从未发生**。继续加功能的边际价值低于先跑通一次真实复用。
**建议**：下一阶段安排一次“验收冲刺”，用 3 个真实资产各走一遍场景 1 和场景 2，记录卡点再修。

### 8.2 遗漏：使用反馈闭环（E01）完全缺失

资产复用是第一优先级，但系统不知道哪个资产被用过、用在哪、效果如何。没有这个闭环，“持续进化”（R13）无从谈起，资产库也会慢慢变成收藏夹。
**建议最小版**：
- 复制和交付时自动记录时间与次数（无需用户操作）。
- 详情页提供一键“好用 / 需改进”和可选备注。
- 列表支持按“最近使用”排序，显示“从未使用”标记。

### 8.3 遗漏：没有“待处理”汇总入口

需要你判断的事项分散在各页深处：知识候选待确认、来源变化需复核、目标副本与固定版本不一致、项目 Current 变化需重新对齐、Agent 目标失效。蓝图 K02 明确要求“重要选择进入用户待决列表”，现在没有这个列表。
**建议**：新增“待处理”视图，或做成首页顶部的汇总条，只聚合、跳转，不在这里执行动作。

### 8.4 随手记与知识体系割裂

随手记只存在工作台主库，这与已确认的“笔记在 Obsidian”（Q06）冲突。v0.16 已经实现了“受控新建到 00 待整理 + 回读 + 撤回”，**可以直接复用来完成随手记归位（K03）**，成本低、价值直接。

### 8.5 知识整理的手工摩擦过高

整理流程是：复制任务文本 → 到 Codex 执行 → 复制候选 JSON → 贴回工作台，每次要来回切换好几次。在单目标执行（W02）到来之前，可以先简化这一步，例如让 Codex 把候选写入约定位置，工作台去读取。

### 8.6 搜索能力弱

- ⌘K 只匹配资产**标题**和页面名，不搜正文、标签、项目、知识和参考。
- 资产库没有标签筛选（蓝图写明的是“搜索 / 标签 / 来源筛选”）。

### 8.7 导航没有区分成熟度

“夜间模式”“模型与设置”“拆解与参考”只是草稿，却和成熟功能占据同级入口，容易误以为可用。“知识连接”这个名字也装不下查询、整理、保存和维护四件事。
**建议**：草稿入口统一加“规划中”标记；把“知识连接”改名为“知识”，页内分成 连接 / 查询 / 整理 / 维护 四个子页签。

### 8.8 第三方 Skill 没有安全准入

ZIP 结构校验防的是路径逃逸，不是恶意指令。从外部收录的 Skill 可能带有危险脚本或提示注入。
**建议**：收录时标记来源可信度，列出包内可执行文件和脚本；未审阅的第三方 Skill 在复制口令处给出提示。

### 8.9 交付形态门槛

使用前要在终端运行 `npm start`，重启后临时链接全部失效，普通导出也不包含恢复日志。对日常使用者来说，这是持续的摩擦和风险。
**建议**：增加 macOS LaunchAgent 开机常驻（需要你授权），另加“完整数据目录备份”功能。

## 10. UI 方向：数码宝贝进化风格（新要求，待定稿）

### 10.1 背景：必须先知道的历史

- **2026-09-27**：你批准过一版深海蓝数码档案风（参考图 `design/digievolution-v1/reference/approved.png`，含初代伙伴角色图）。
- 同一天改为全部线稿 SVG。
- **2026-09-28**：你要求“还原原来的视觉，不要数码宝贝版本，回滚”，当前界面是回滚后的“归集”米白暖橙风。
- 那两版都**没有在浏览器里看过真实效果**（当时浏览器访问被拦截），可能是实际观感不达预期。**现在浏览器已经可以用，本轮可以逐页截图核对。**

**你的反馈（2026-09-28）**：上一版“太复杂”，要求重新设计，并**注意动效和细节**。

据此，本次设计的取舍如下：
- **做减法**：不用角色贴图群像、文件岛插画、八徽章横幅、双栏密集布局，也不堆装饰。
- **保留**：现有的“侧栏 + 卡片网格 + 详情抽屉”信息结构，它已经验证过、用户熟悉。
- **特色来源**从“画面元素多”转向三点：
  1. 少量标志性符号：数码蛋、数码暴龙机液晶屏、进化光。
  2. 精致的材质和微细节。
  3. 有意义的动效：进化、数据化出现、锁定选中。

### 10.2 设计目标

“质感更强、更有特色”。拆解为可检验的要求：

1. **有辨识度的世界观**：数码世界、神圣计划、数码兽进化的视觉语言，而不只是换一套配色。
2. **质感**：层次（玻璃或金属面板、发光描边、像素或网格纹理、扫描线）、光效和动效（进化光柱、数据流）。克制使用，不影响阅读。
3. **功能语义挂钩**，让主题为功能服务：
   - **资产成熟度 = 进化阶段**，基于真实证据自动判定，不许虚构：

     | 进化阶段 | 对应资产状态 |
     |---|---|
     | 幼年期 | 线索或草稿 |
     | 成长期 | 已收录 |
     | 成熟期 | 已复用（有使用记录） |
     | 完全体 | 已验证（有正向反馈） |
     | 究极体 | 核心资产（多目标、多次有效） |

     这个映射依赖 §8.2 的使用记录，**两者可以一起做**。
   - 版本升级 = 进化动画；恢复旧版本 = 退化（新增版本）。
   - 八大徽章 → 资产分类或标签的视觉符号（勇气、友情、知识……）。
   - Agent 可以表现为“伙伴”，但证据分层（检测到 / 已管理 / 已采用）必须照常清楚显示。
4. **不牺牲可用性**：对比度达到 WCAG AA，键盘和焦点完整，窄屏可用；9 个页面的全部真实功能和安全语义不变。

### 10.3 版权与素材边界

数码宝贝角色和徽章受版权保护。仅限本机个人使用可以考虑，但**不能用于公开发布**。素材来源（你提供的图、自绘线稿，或原创“数码风”伙伴）需要你决定。原创设计可以避开版权问题，也更有“你自己的”特色。

### 10.4 v3 方向原型（2026-09-28，待你确认）

原型文件：[design/digievolution-v3/prototype.html](design/digievolution-v3/prototype.html)，单个 HTML，双击即可打开。只覆盖资产库页，使用种子数据，不接后端。

**做了减法**：
- 布局保持原来的“侧栏 + 卡片网格 + 详情抽屉”。
- 不用角色图、岛屿插画、徽章横幅，也没有双栏。
- 符号只保留三类：
  - 像素数码蛋，用作 Logo 和启动画面。
  - 液晶点阵封面：每种资产类型对应一个像素图标，Skill 是晶体，Prompt 是对话框，工作流是节点链。
  - 五格进化阶段条。

**材质**：

**动效清单**（系统开启“减少动态效果”时全部关闭）：

| 时机 | 效果 | 时长 |
|---|---|---|
| 启动 | 数码蛋像素逐个点亮 → 抖动 → 孵化闪光 → 界面淡入 | 约 1.7 秒，仅首次加载 |

| 卡片悬停 | 四角锁定框收拢，液晶屏扫描线扫过，图标轻微放大；选中时锁定框变橙并保持 | |
| 筛选切换 | 指示块平滑滑动 | |

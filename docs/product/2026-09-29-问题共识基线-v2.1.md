## 核心复述

用户要的是一个能管理全部个人 AI 能力的操作台，而不是功能更多的工具箱。它由三层加一条回路组成：

- 资产层：我有什么。
- 目标层：交给谁用、在哪里用。
- 运行层：怎么跑起来。
- 进化回路：用过留下证据，凭证据改版，并把日常中新产生的方法回收进来。

之前觉得“不清晰”，是因为 14 个模块平铺、没有骨架，而且协同、harness、进化这三个概念没有具体形态。并不是缺少模块。

## 希望改变的现状与预期结果

**当前情况：**
- 模块之间是什么关系说不清。
- Hermes×Codex 的协同探索放在工作台之外单独进行。
- Skill 散在 4 处并大量断链：Claude 和 Hermes 各有 233 个链接失效。
- Claude 与 Codex 之间靠用户手动传话接力。

**期望改变：**
- 用一套骨架就能说清每个功能的位置和依赖。
- 每个概念都有可落地的形态。
- 以后日常只看工作台：资产、Agent、项目、日历、待处理都在这里。

**判断问题得到解决的初步依据：**
1. 用户能用一张结构图讲清全部模块的关系。
2. 原始想法逐条能在台账中找到位置、层级和时域。
3. 更新后的路线里，每项需求都有承接切片，并且不破坏第一阶段的验收节奏。

## 方案需要回答的关键问题

1. Skill 公用池“以工作台为权威、发布、按 Agent 挂载”怎样衔接现有资产库和复制口令？现有断链怎么处理？
2. 运行层的最小可靠单元怎样借用 Hermes/Codex 的原生能力，而不重写执行内核？
3. 日历用 macOS 日历作为数据源，怎样写回和回读？怎样服务“提前规划时间”？
4. 新增能力怎样插入路线，又不破坏“第一阶段整体验收通过前不进第二阶段”？
5. 怎样证明进化真的发生，而不是只多了一些候选？

## 2. 排序依据

按四个问题排序：
1. 什么可能推翻路线，需要先验证？
2. 主流程怎么跑通？
3. 哪些价值大、反馈快？
4. 现在做、随后做、暂不做分别是什么？

难易程度不单独决定顺序。

- **可能推翻路线的未知，放在各自切片的开头做最小验证：**
  - Codex 等三个 Agent 能否发现共享池里的 Skill（2.1）；
  - macOS 日历能否读写（3.2）；
  - Hermes 夜间执行能否如实记账（3.3）；
  - 监工在真实项目上是减负还是增负（平行支线 P1）。
- **主流程：** “资产收得进、发得出、在 Agent 里用得上”（第一、二阶段），之后是“每天打开工作台看安排、看待处理、交代任务、收成果”（第三阶段）。
- **价值与反馈：** Skill 发布与体检直接解决现存的 233 个断链和 Skill 散落在 4 处的问题，最快见效；接力的 a 层直接减少你在两个客户端之间传话。

## 3. 需要你决定的两点

**R1 · 是否把“每日入口”提到“Agent 管理”之前**（涉及对已确认优先级 A ＞ B ＞ C ＞ D 的例外）

“每日入口”指常驻、日历、夜间第一版、进化回路。

- **方案 1（推荐）：提前。** 顺序为资产 → 资产分发 → 每日入口 → Agent 管理 → 知识 → 协同与执行。理由有四条：
  1. 常驻是日历提醒和夜间运行的共同前提；
  2. 你希望以后都看工作台，每天用起来才会产生进化回路所需的使用证据；
  3. 夜间第一版只做只读体检和知识候选，执行交给 Hermes，不属于“先造执行引擎”；
  4. Agent 管理的主要事项（切换 API、迁移配置、修复）每一步都要你授权真实配置，放在工作台已经天天在用之后更稳。
- **方案 2：严格按 A ＞ B ＞ C ＞ D。** 资产分发之后先做 Agent 管理，再做每日入口。

**R2 · 以后的验收节奏**

- **方案 1（推荐）：每个阶段末做一次整体验收**，延续你对第一阶段的选择。代价是问题会在阶段内累积。缓解办法是每个阶段只放 3 到 5 个切片，并且每个切片仍经过另一方复核。
- **方案 2：每个切片都做真人验收**，即原 ROADMAP §3 的硬规则。

下文按 R1、R2 都选方案 1 排列。如果 R1 选方案 2，第三阶段和第四阶段互换。

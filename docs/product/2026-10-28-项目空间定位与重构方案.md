## 0. 结论先行

**一句话**：项目空间是**名册里每个项目的只读档案**——为什么做、现在到哪、这个项目实际用了我的哪些技能。它不是派活的地方，也不是收东西的地方。

**它是什么**

1. **项目图鉴**：名册里在管的项目一页看全，每个项目一张卡带。
2. **档案与现在**：为什么做（Vault 项目卡摘要）、现在到哪（CURRENT 顶节、开着的 issue / PR、未推送、30 天提交），全部只读。
3. **实战**：近 30 天在这个项目的会话里**实际调用过哪些技能、几次、最近哪天**，自动从本机会话记录统计（只记名字、次数、日期，不读内容）；没收录进资产仓库的技能一键收录。这是数码世界独有的东西：仓库里有项目上下文，但没有“我在这个项目上用了哪些能力”的记录。

**它不是什么**

- 不是派单台、接力台、提醒器：派单和回流归 Hermes（数字分身 F5、F6），任务看板归各仓库 GitHub Issues（M3-Q7）。
- 不是收件处：便签属于哪个项目、处理完没有，是随手记自己的事（§3.3）。
- 不是装备配置台：不让你手工登记“这个项目用哪些资产”，用了什么从会话记录里自动看出来。
- 不是项目进度的真源：进度在仓库 `CURRENT.md` 和 GitHub；项目的“为什么”在 Vault 项目卡。只读、只摘要、只链接。
- 不是目录扫描器：项目以数字分身的名册 `projects.json` 为准；扫描只在设置里用来发现新目录。
- 不和牛马之家交换数据：牛马之家只是名册里的一个项目，读它仓库里的 CURRENT 和 git，和读其他项目一样。

**为什么这样改**

- 10-24 定稿的 4-1 交接条把「复制口令，交给 X」做成主角；10-26/27 常浩在数字分身里定了「数码世界收缩成看板和资产库，调度、接力、提醒不再做」（数字分身 D10、Q5）。按最新结论，主角要换。
- 第一版方案曾把「装备」「收件」立为主角。查真实数据（§2.2）后发现：两者**都没用起来，也很难用起来**——收件只多一道手续，手工装备和实际在对话里用技能是两套账。真正的使用发生在会话里，而会话记录里能清楚认出用了哪些技能。所以改成读真实使用，而不是让人手工登记。

使用场景（按频率）：

1. **开工前扫一眼**：哪些项目在动、哪个停了、哪个 CURRENT 很久没更新、哪个 issue 堆着。
2. **整理资产时**：看某个项目最近靠哪些技能在推进，把反复用、还没收录的技能收进资产仓库。
3. **回顾一个项目**：这段时间在这个项目上主要用了什么方法（如牛马之家近 30 天 `lark-doc` 15 次、`grilling` 11 次、`code-review` 10 次）。

## 4. 在整个工作台里的位置与串联

### 4.1 主线怎么重新解释

深度评审的主线「捕获 → 孵化 → 进化 → 出战」保留，“出战”的含义改为**“在项目里真的被用上”**，而且由会话记录自动证明，不靠手工登记：

```
随手记 / 个人收藏 ──孵化──▶ 资产仓库 ◀── 逆向工程（孵化器，存成 Skill）
                              ▲     │
                     收录（M6）│     │ 进化证据（L1）
                              │     ▼
本机会话记录 ──只读元数据──▶ 项目空间·实战 ──置顶项目──▶ 世界总览·项目块
（Claude Code / Codex）          │
                                └─以后 L2：Hermes 通过 MCP 来取

只读来源：digital-twin/projects.json（名册）· Vault 10 项目/*.md（项目卡）· 各仓库 CURRENT.md + git + GitHub（现在）
```

### 4.2 逐模块关系

| 模块 | 进项目空间 | 出项目空间 | 入口 |
|---|---|---|---|
| 资产仓库 | 已收录的 Skill（显示进化阶段） | 收录未收录的技能；Skill 详情显示“用在哪些项目” | 实战行「收录」；资产详情点项目名跳过来 |
| 随手记 | 无（收件移出） | 无 | 便签的项目归属与处理状态在随手记里做 |
| 个人收藏 | 无 | 无 | — |
| 逆向工程 | 无直接连线：存成 Skill 进资产仓库，被用到时出现在实战里 | — | — |
| 世界总览 | — | 置顶项目的一句话“现在” | 总览项目块点击进入对应项目 |
| 设置 | 名册路径、Vault 只读授权、**会话技能统计开关** | — | 设置 → 目录与扫描；页头齿轮直达 |

## 5. 信息架构与页面布局（定稿：电路卡带 · 7E）

来历：
- 第三版 [5-图鉴](../design/ui-v19/项目空间-5-图鉴.html) 被用户评为“没气势”。第六轮出三版电脑稿：6A 主卡、6B 卡带、6C 名册栏。

卡带规则：

- **一盘 = 名册里的一个项目**，置顶在前，名字后一个小橙块表示置顶。每个项目有固定的代表色和两字母代号：数码世界青、牛马之家黄、数字分身紫、GitHub 快速中心粉、agent-kit 绿、自建技能库灰蓝、CarvoMOTO 橙。代表色和代号从哪里来，在落代码方案里定。
- **机壳只写一件最该注意的事**，按下面的顺序取第一条：
  1. 待人工验收
  2. 下一步可能过期
  3. 未推送超过 10 个
  4. 待 Agent
  5. PR 待合并
  6. 没有 GitHub 远端
  7. 以上都没有时，写最近提交日期

  第 1、2、3、6 条标黄，其余用普通字色。
- **灯**放在“要注意的事”那一行的右端，只表示近 7 天有没有提交。
- **选中的那盘**：走线常亮一圈代表色光晕（静态），过孔变亮，触点发光。选中的那一刻，一道亮光沿走线按帧跑一遍（12 帧，约 0.7 秒），跑完停在常亮的光晕上。不做常驻的循环流光，因为 v19 定过「按帧、有因果、一次到位；不做常驻的飘动、呼吸、扫描线」。用户开了“减少动态效果”时没有这道流光，只有光晕。
- 点卡带：卡带按下一帧，档案屏扫描线刷一遍，档案屏换成这个项目，五个读数滚动到位。

档案屏取舍（第七版）：

- **删掉的说明文字**：「CURRENT 顶节」来源标签（默认就是 CURRENT，只在来源是提交时写明）、实战小标题里的「Claude Code 会话」、每行的「未收录」字样（改成右上角汇总「未收录 N」，已收录的行单独标出）、Codex 那句解释（缩成「仅参考」）、页脚「目录扫描已移到设置」、旧口令按钮后面的「旧功能，不再扩展」、本机路径（挪到「详情」按钮的提示里）。
- **改成直接摆出的**：目标与不做，不再折叠；五个读数并排成一条，下面一行只写拆分（待 Agent / 待人工、15 天有提交、17 个技能 · 35 个会话），没有可拆的就空着。

- **实战**：两列，默认显示前 10 个，每行是技能名、来源、紫色像素格、次数、最近日期。悬停在一行上时，最近日期换成「收录」按钮。这个项目近 30 天没有技能调用时，整段只剩一行字。

### 5.3 视觉（沿用 UI v4 / v19，不改伙伴屏）

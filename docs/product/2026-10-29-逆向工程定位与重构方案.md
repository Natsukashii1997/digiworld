## 0. 结论先行

**一句话（建议）**：逆向工程收缩成一张**拆解单**：看到好东西，写清它好在哪，交给原生 Agent 去拆，拆出来的做法收进资产仓库。工作台只负责立项、存档和收成，**不再自己执行取证**。

**它是什么**

1. **立项**：参照物（链接、截图、本机路径）、想弄懂什么，「好在哪里」选填。正式库里 3 条记录的「好在哪里」都没填过，所以主字段是「想弄懂什么」（10-29 做样稿时查到，更正初稿）。
2. **交出**：一份任务包，复制给 Codex 或 Claude Code。软件类的任务包写明「用你本机已注册的 rea MCP 取证」。
3. **收成**：把 Agent 的结论贴回来，存成固定版本的 Skill 或 Prompt。资产带上来源（`origin: reverse`），以后被用上时，会出现在项目空间的「实战」里。

**它不是什么**

- 不是取证执行台：REA 运行、AI 执行器、内嵌的 Codex 会话都交还原生 Agent。Claude Code 和 Codex 都已经注册了 rea MCP 和 `reverse-engineer-anything` skill，在原生会话里取证体验更完整。
- 不是 REA 的维护台：版本检查、预演、双客户端更新挪到设置。
- 不是另一个聊天工作台：不在页面里发起或续聊会话。

**为什么这样改**

- 投入最大、使用最少（§2）。正式库一共 3 条记录，存成 Skill 0 次，复制任务包 0 次；10-20 之后没有新增。
- 现在这一页违背了已定的原则：AGENTS.md 规定「日常执行仍在原生 Agent 中，不改造成另一个聊天工作台」；数字分身 D10 和 Q5 定了「收缩成看板和资产库」。
- 这页真正独有的价值，是**把一件参照物和最后得到的资产连成一条可追溯的线**。原生 Agent 能拆，但不会替你记下「为什么拆、拆出了什么、后来用上没有」。

## 1. 对应常浩的哪些目标和场景

| 来源 | 目标 / 场景 | 逆向工程承担什么 | 不承担什么 |
|---|---|---|---|
| 数字分身 PRD D10、Q5 | 工作台收缩成看板和资产库 | 只做立项、存档、收成 | 不执行，不调度 |
| 本仓库 AGENTS.md 持续约束 1 | 日常执行在原生 Agent 中 | 产出任务包，交给原生 Agent | 不内嵌会话，不直接调用 CLI |
| 深度评审 §3（10-23 确认 D2） | 逆向是资产的孵化器 | 唯一出口是资产仓库 | — |
| 深度评审 §4.2 根因 4 | 进化回路缺燃料 | 资产带上来源，可以追到参照物 | — |
| 项目空间方案 §4.1 | 出战 = 在项目里真的被用上 | 来自逆向的 Skill 被用上时，出现在实战里 | 不手工登记 |

使用场景（建议，按频率）：

1. **看到一个好网站、好功能、好文案**：顺手开一张拆解单，写下「好在哪里」，复制任务包交出去。
2. **Agent 拆完**：把结论贴回，存成 Skill，以后在资产仓库里直接复用。
3. **回头看**：某个 Skill 是从哪件参照物拆来的，当时为什么觉得它好。

## 3. 功能清单：必须 / 以后再说 / 不做

### 3.1 必须（这次重构做）

- **M1 孵化器页面**（10-29 选定 3C，取代原「三段卡」）：一件标本一台孵化器，Skill 的八格在两边，详见页面简报 [05-reverse.md](../design/ui-v19/briefs/05-reverse.md)。
- **M2 软件类任务包改写**：任务包写明目标、SHA 前 8 位（有单一文件时）、想弄懂的功能、线索，要求原生 Agent 用本机 rea MCP 取证，区分观察、推断和未知，并先列验收用例。不再依赖工作台本机运行得到的证据 ID。
- **M3 收成可回贴**：支持粘贴 Agent 的结论文字，按八格拆进格子（简报 §4.1）。存成 Skill 时沿用现有的「预览 → 确认 → 同 revision 固定版本 → 回读」，并注明「未经复刻验证」。
- **M4 资产来源**：资产版本写入 `origin: {kind: reverse, id}`（深度评审 §7.2 已有设计）；资产详情显示「来自参照物 X」，点击可以跳回来。
- **M5 标本切换**：页头下一行横滑切换标本（3C），替代「全部 / 软件 / 作品」筛选。
- **M6 冻结执行入口**：页面不再显示 REA 运行、AI 执行器、Codex 会话和预检；旧记录的历史取证收进折叠区只读。
- **M7 REA 维护挪到设置**：版本读数、检查更新、预演和确认，整块挪到设置的「对外接口 / 工具」组，能力不变。
- **M8 追问未知**（10-29 做样稿时新增）：下一轮任务包从没填满的格子生成，只问这些问题；复制后这些格子标「第 N 轮在问」。依据是真实记录：「Agent迁移」第 1 轮的 4 个未知直接决定了第 2 轮怎么问。
- **M9 八格回答格式**：任务包要求 Agent 按八格回答（每格写已知和缺）；旧结论显示「未分格」，可以生成「按八格整理」的任务包（简报 §4.4）。

### 3.2 以后再说

- **L1 拿去拆解**：在收藏和随手记的条目上加一个入口，带着链接和文字新建拆解单。
- **L2 收成提醒**：已交出超过 7 天还没收成的，在列表里标黄。

### 3.3 不做

- 不在工作台里调用 AI、不内嵌会话、不跑 REA。
- 不恢复复刻评分、达标线和炼成门（v4 已去掉）。
- 不自动抓取参照物正文，不联网读目标。
- 不删除任何历史记录、证据或固定版本。

## 4. 在整个工作台里的位置与串联

```
个人收藏 / 随手记 ──（L1 拿去拆解）──▶ 逆向工程·拆解单
                                       │ 复制任务包
                                       ▼
                         原生 Agent（Codex / Claude Code + rea MCP）
                                       │ 结论贴回
                                       ▼
                          收成 ──存成 Skill（origin: reverse）──▶ 资产仓库
                                                                   │
                                                 会话里被用上 ──▶ 项目空间·实战

REA 版本与更新 ──▶ 设置·对外接口 / 工具
```

| 模块 | 进逆向工程 | 出逆向工程 | 入口 |
|---|---|---|---|
| 资产仓库 | — | 存成的 Skill / Prompt，带来源 | 收成卡「已收成 → 资产名」；资产详情「来自参照物」 |
| 个人收藏 / 随手记 | 链接、文字（L1） | — | 条目上的「拿去拆解」（L1） |
| 项目空间 | — | 来自逆向的 Skill 被用上时出现在实战里 | 无直接入口 |
| 设置 | — | REA 版本与更新 | 设置 → 对外接口 / 工具 |
| 原生 Agent | 结论文字（手动贴回） | 任务包（手动复制） | 不自动发送，不自动输入 |

## 5. 信息架构与页面布局（定稿：3C 孵蛋）

10-29 用户选定 **3C 孵蛋**。页面结构、元素、交互、状态和手机布局都以页面简报 [05-reverse.md](../design/ui-v19/briefs/05-reverse.md) 为准；视觉稿是 [逆向工程-3C-孵蛋精修.html](../design/ui-v19/逆向工程-3C-孵蛋精修.html)。

一句话：中间一台 Skill 孵化器（数码蛋 = Skill），两边是这份 Skill 的八个格子。填上的格子亮绿，蛋在对应一侧裂开；空格一键写成下一轮追问包，复制给原生 Agent；什么时候都能孵化，空格写进「局限」。

选版过程：第一轮三版（工单台、孵化流水、解剖屏）被否，评价是只换了流程的排法；第二轮按「每轮的未知就是下一轮的问题」重想，出了透视图、回合、孵蛋三版；第三轮精修透视图和孵蛋，选定孵蛋。各轮稿件和截图都在 `docs/design/ui-v19/`。

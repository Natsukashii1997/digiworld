日期：2026-11-07｜作者：Claude｜状态：**定稿**。依据常浩与 ChatGPT 讨论定稿的《个人 AI 项目体系重构 V1.3》（决定记录在 digital-twin `docs/项目体系重构/`，以下简称 V1.3），以及常浩 11-07 的原话。

**替代关系**：本文件替代 [产品定义 v1.2](2026-09-30-产品定义-v1.2.md)、[v1.1](2026-09-29-产品定义-v1.1.md) 和 [PRD.md](../../PRD.md) 中关于「产品是什么、管什么、能写什么」的部分。三者里与本文冲突的表述，一律以本文为准（作废清单见第 5 节）。PRD 里其他细节（UI v4 视觉、非功能需求等）在没有冲突时继续有效。

## 1. 一句话定义

**数码世界是常浩个人 AI 体系的信息驾驶舱**：接各项目、各 Agent、各资产的权威来源，把它们汇总并可视化，让常浩快速和自己整个 AI 体系同频。

它回答三个问题：
1. 我现在有哪些项目、Agent、自建 Skill、Prompt 和其他资产？
2. 它们各自进展到哪里、状态如何、最近有什么变化？
3. 要继续处理某一项，应该去哪里？

常浩原话（2026-11-07）：「它是接收到不同项目的接口，把数据都能够在这里有可视化的显现……只做展示，少部分带有这个写入编辑的功能，大多数的定位就是在信息汇总、信息中枢这样一个定位。」

它**不是**：项目管理的权威中心，自建 Skill 的生产和维护中心，第三方 Skill 的收藏库，多 Agent 的执行编排器，也不是另一个聊天窗口。

## 2. 唯一权威源（数码世界只读）

| 对象 | 权威源 | 数码世界做什么 |
|---|---|---|
| 正式项目与类型 | `digital-twin/projects.json` | 只读展示、状态汇总、跳转 |
| 项目进度与验收 | 各项目 `CURRENT.md`、GitHub 状态 | 只读聚合，标来源、读取时间和「未知」 |
| 自建 Skill | `my-skills` 仓库，经 `catalog/skills.json` 索引 | 只读展示，不写回 |
| 第三方 Skill、外部开源项目 | GitHub 中心 | 不管理，最多提供跳转 |
| Agent 全局指令与正式规则 | Vault（P-xx）、agent-kit（G-xx）、各项目 AGENTS.md | 按白名单只读查看或跳转，不安装、不覆盖 |
| Vault 知识正文 | 本机 Vault | 只读展示经授权的状态与摘要，不外发 |
| 多 Agent 模式、DT-ORC 任务、Multica 运行记录 | multi-agent、digital-twin、Multica run-log | 需要时只读汇总 |

缓存、索引和统计可以有，但**不因为记录了这些信息就成为新的权威源**；缓存不能反向覆盖来源。来源读取失败时显示上一次可信快照，并标明「过期」，不显示成正常。

## 3. 模块权限矩阵

| 页面 / 能力 | 目标 | 要点 |
|---|---|---|
| 首页 | 只读总览 | 项目、Agent、自建 Skill、Prompt 等数量和最近变化；每项标来源和更新时间 |
| 项目空间 | 只读正式名册 | 只保留置顶、筛选等显示偏好；下线可编辑项目目录和扫描写入 |
| 自建 Skill | 只读展示 my-skills | 下线 ZIP 上传、编辑、版本恢复、个人改版、目标副本、交付链接、发布到 Agent 或共享池，以及所有对应的写接口 |
| 第三方 Skill | 移除 | 归 GitHub 中心 |
| Prompt | 可写（自有数据） | 和 Skill 同存 `assets[]`，改造时不得误删 |
| 普通规则模板 | 可写模板；禁止「装入项目」 | 规则要生效，必须回到原项目和权威系统 |
| 工作流草稿、设计素材 | 可写（自有数据） | 只编辑素材和模板；「部署到项目工作区」属于跨项目写入，一并下线，必要时改为仅导出 |
| 正式全局规则 | 新增只读来源查看 | Vault P-xx 是受限内容，只显示出处和摘要，不默认展示全文 |
| Agent | 独立只读页（D-A） | 见第 4 节 |
| 随手记 | 可写（自有数据） | — |
| 学习 / 收藏集 | 暂保留可写 | 和 GitHub 中心的重叠另行核查 |
| 参考 / 逆向工程 | 保留参考分析；产出的 Skill 进 my-skills 候选（D-B） | 不再往数码世界的 Skill 库写 |
| 知识 | 只读审计后再定 | 写回目标是 Vault `00 待整理/`，未经确认不写 Vault |
| 夜间执行 | 只读审计后再定 | 原则上信息驾驶舱不再拥有第二套自治执行器 |
| 日历 | 只读展示 | — |
| 接力包 | 暂保留轻量文本和导航 | 实际传信、回执归驿窗；不产生第二份协同模式定义 |

## 4. 两个已定的决定

- **D-A（Agent 写能力全部下线）**：取消数码世界对真实 Agent 的一切直接写入，包括：
  - 配置文件、模型；
  - 正式指令文件（AGENTS.md、CLAUDE.md、SOUL.md）；
  - Skill 安装、发布、启停，共享池；
  - 挂载修复、跨 Agent 迁移。

  设置页里的 Agent 功能重构为独立的只读 Agent 页，每个常用 Agent 显示：
  - 定位；
  - 全局指令文件全文：按允许路径白名单读取，敏感字段脱敏，受限内容只给出处；
  - 路径与更新时间、当前模型、已装 Skill（标明来自 my-skills 的）、MCP 清单；
  - 额度或在线状态（有证据才显示）；
  - 来源与读取时间。

  验收要求：写能力前后端同时失效，绕过界面直接请求写接口也必须被拒绝。只隐藏按钮不算完成。
- **D-B（逆向产出改道）**：逆向工程产出的 Skill 进入 my-skills 七站的「候选」一站（issue、草稿包、来源指针），不写数码世界的 Skill 库，未经准入不得安装到任何 Agent。

## 6. 改造顺序

按总票 #67 的子票依次做（I-DW-1 到 I-DW-9）。每一张开工前先做快照备份；删写接口必须同时有后端负向测试；Prompt、规则模板、工作流、设计、随手记的数据和功能不能受影响。

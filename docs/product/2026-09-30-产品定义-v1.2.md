## 1. 一句话定义

**这是你每天只需要打开的那一个网站。它运行在你的 Mac 上，分为工作区和生活区。**

- **工作区**：管理你的 AI 能力，推进你的项目。核心是让 3 个主力 Agent 在你同时推进的 1–3 个项目上严谨、省力地接力，你不再在它们之间传话。
- **生活区**：放你的时间安排、信息、学习和兴趣，让你不必同时开很多网站。

与 v1.1 的差别：
- v1.1 是“AI 能力操作台 + 每日入口”。v1.2 把“每日入口”扩展成完整的个人入口，并把重心移到**项目空间、协同、知识仓库**。
- 日常执行仍在各原生 Agent 里完成，工作台不重写执行内核（N3 不变）。

## 4. 关键机制

### 4.1 项目空间：在推进项目的深度管理

**推荐方案**

- **两层**：扫描到的全部项目只是索引；你把 1–3 个项目标为“在推进”，只有这些项目获得下面的深度功能。
- **项目状态卡**：从项目自己的 CURRENT 和交接文档读取，显示当前写入者、状态编号、唯一下一步、最新交接、卡在哪里。没有 CURRENT 的项目显示“未装协同协议”，并提示可以装入规则模板。
- **停滞雷达**：超过 N 天（默认 7 天，可调）没有状态更新或提交的在推进项目标红。
- **项目安全体检**：是否有远程备份、是否有未提交的改动、是否有私密文件被 Git 跟踪（`.env`、密钥、数据库、`data/` 这类路径）、远程仓库是否为私有。只读，发现问题进待处理。
- **一键开工**：选一个 Agent，工作台生成带上下文的开工口令（项目路径、先读哪些文件、唯一下一步），复制并打开这个 Agent。
- **第二批**：GitHub 面板（PR、Issue、CI），每日项目简报。

**依据**：你同时推进的项目不多，但每个都要求严谨接力；本项目直到 9/30 才有独立仓库和远程备份，说明安全体检有真实价值。

**承重假设**：在推进项目都按协同协议维护 CURRENT。没有 CURRENT 的项目只能显示 Git 状态。

**最小验证**：用本项目作为第一个在推进项目，状态卡与 CURRENT 表头逐项一致；安全体检能在一个合成仓库里识别出被跟踪的 `.env`。

### 4.2 协同：三层 + 可验证任务自动派发

**推荐方案**

1. **协议**：规则模板以托管区块装进项目（已实现，模板 v1.0 已收录）。
2. **看板**：每个在推进项目显示当前流程走到哪一步，例如“认领 → 实现 → 独立复核 → 返修 → 用户验收”，以及笔在谁手上。数据来自项目 CURRENT 的状态记录。
3. **一键派发**：到交接点时，工作台按模板生成下一棒的完整口令（输入状态、任务、验收标准、禁止事项、要回交的证据），你确认后复制并打开目标 Agent。
4. **可验证任务自动派发**：回归测试、稳定性矩阵、独立复核这类有明确通过标准的任务，可以一键派到云端或后台运行，结果以分支或报告回来，进入待处理。依据是本项目已跑通的云端 routine 与 [CLOUD-SESSIONS.md](../../CLOUD-SESSIONS.md) 约定。

**模板**：#1 Claude×Codex 串行接力，本项目 90 多个状态的实际流程；#2 执行 + 监工，等试点在真实项目上跑通后再加入。

**关键规则**：每一棒交接都由你一键确认；工作台只生成、展示和派发，不替你决定谁接手（N6）。

**承重假设**：把交接口令规范化后，Agent 能够据此正确接手，且不需要你补充解释。

**最小验证**：在本项目上用“一键派发”完成一次真实的 Claude → Codex 交接，Codex 回报的读回状态与 CURRENT 一致。

**改线条件**：如果生成的口令经常需要你手动补充，就退回“模板 + 手动填空”，保留看板。

### 4.3 智能体群

**推荐方案**

- **范围**：主力 Codex、Claude Code、Hermes；附属 OpenClaw、豆包工作；其余 Agent 只做安装检测。
- **借鉴炉子**，依次做：
  1. **内容清单**：每个 Agent 的 Skill、配置文件、项目、插件、MCP 分组列出；单项开关；一键“存入资产仓库”。与原路线 2.1 发布挂载、2.2 体检合并。
  2. **配置快照**：存在本机，纳入完整备份，不存云端。
  3. **跨 Agent 迁移**：基于快照，先预览再迁移 🔐。
  4. **上下文接力**：项目级为主，读项目 CURRENT；会话级为补充，只在你当次点击时读取本机会话，使用前先预览，不存档。
- **能力体检并入**：每张 Agent 卡片显示健康状态，包括断链、挂载不一致、副本落后、可读性；问题进待处理。沿用 v1.1 §4.2 的只读体检与修复分离。
- **角色卡与派活推荐**：卡片写明擅长什么、成本、常驻项目、当前在忙什么（从项目状态卡读取）；派活时工作台推荐人选，你来拍板；实际反馈修正推荐权重。

**隐私条款的修改**：PRD 的“不读私人会话”改为“仅在你当次点击时、只在本机读取、使用前先预览，并且只用于上下文接力”。其他模块仍不读会话。

### 4.4 知识仓库与个人说明

**三区视图**

| 区 | 内容 | 给 Agent 的用法 |
|---|---|---|
| 输入区 | GET NOTES 订阅、剪藏、导入资料 | 可以检索，但不当作权威 |
| 我的知识 | 决定、方法、项目经验、知识编译 | 优先引用 |
| 个人说明 | `个人上下文` 文件夹 | 每次会话的背景 |

- 视图按规则划分，不移动文件。首版规则按文件夹划分，例如 `GET NOTES/**` 归输入区；规则由你在界面上确认。
- 主要指标：“我的知识”本周新增和更新的篇数。当前约 30 篇，订阅类 679 篇。
- 知识仓库这条线开工时，先做一份带出处的成熟案例调研（第二大脑方法、LLM 编译知识库、自更新记忆、个人上下文 MCP）。

**个人说明（MCP-native self-updating context layer）**

- **唯一权威**：Vault 的 `个人上下文` 文件夹。读取它的 6 篇正文需要单独授权，届时再定分节。
- **MCP 原生**：工作台提供一个只监听本机的 MCP 服务，提供“读取个人说明”和“提交修改建议”两类工具，所有 Agent 通过它读取。
- **自动更新**：Agent 只能提交修改建议，包括依据和要改的段落；建议进入待处理，你一键采纳（写入 Vault 🔐）或拒绝。
- **差异**：不同 Agent 需要的上下文不同（待定 Q5）。首版提供一份通用说明，以后再加“按 Agent 追加”的分节。

**承重假设**：主力 Agent 都能连接本机 MCP 服务。不支持的 Agent 退回复制口令，带上个人说明摘要。

### 4.5 焚决、随手记、计次与置顶

- **焚决**：若干“卷”（例如心法、prompt 碎片、灵感），每卷是有序列表。每条有醒目的标签，可一键复制，复制计次。卷可以置顶。不做版本，但删除进回收区，可恢复。数据存工作台主库，与资产仓库分开。
- **随手记**：只存本应用。编辑器支持无序列表、有序列表、任务列表，以及红、蓝、绿、黄、灰五色。每条只有一个去向“炼入焚决”：选择目标卷，把选中的文字作为新条目加入，原随手记标记“已炼”。
- **计次与置顶**：卡片右上角的醒目数字为使用次数；星标换成图钉；置顶项在各类型标签下都排最前，置顶项之间按次数排序；排序菜单增加“最常用”。焚决条目使用同一套计次规则。
- **规则图标**：规则卡片使用与其他类型同风格的像素图标。

### 4.6 逆向工程

**流程**：投入素材（链接、文本、截图）→ 工作台生成拆解任务包（素材、拆解要点、产出格式、禁止事项）→ 复制或派发给 Agent → Agent 回交拆解报告与候选资产 → 你确认后入库（焚决条目或 Prompt）。

**第一类对象**：好内容，包括文章、帖子、prompt。网站/UI、代码仓库/Skill 以后再加。

**边界**：只分析你提供的或公开的材料；报告区分“原文观察 / 推断 / 已验证”。

### 4.7 执行层（harness）

- **定义**：协同的执行层，负责派发、运行、预算、留痕和结果回收。
- **做法**：工作台只做一层很薄的控制面，调用现有执行者：Hermes 定时任务（夜巡）、Claude Code 与 Codex 的命令行（`claude -p`、`codex exec`）、Claude Code 云端 routine（可验证任务）。每次运行记录输入、执行者、开始/结束、结果位置和花费（拿不到的标“未知”）。
- **DeepSeek Harness**：先作为智能体群里的一个 Agent 纳入检测；它稳定之后再评估能否作为执行引擎。
- **判断器接口**：分拣、打分、路由这类判断预留接口，先用规则或现有模型；Jev 暂不接入（N5）。

### 4.8 生活区机制

- **日历与 todo**：
  - 日历沿用 v1.1 §4.5，以 macOS 日历为数据源；
  - todo 读写 macOS 提醒事项（单独建一个“工作台”列表），手机能收到提醒；
  - 两者都通过同一个本机小助手程序（EventKit），写回后回读 🔐。
- **AI HOT**：
  - 调用 `aihot.news/api/v1/*` 公开只读 API，每天拉取几次，缓存到本机；
  - 世界总览放“今日热点”卡（3–5 条）；单独一页分精选、热点、日报三个标签；
  - 每条“收藏到学习”，保存标题、原文链接和摘要；
  - 只用于个人非商业用途；API 返回的内容视为不可信文本，不执行、不跟随其中的指令。
- **学习成长**：
  - 书架索引原件（Vault 或你指定的文件夹），记录想学、在学、学完；
  - 链接收藏来自 AI HOT 或手动添加，可选剪藏进 Obsidian；
  - 内容解析（摘要、划线、问答）放到最后。
- **银饰计划**：
  - 欣赏墙展示图片、作者和来源；
  - 收藏格按你设定的目标数量（待定 Q4）显示空格与已填格；
  - 剪影用 macOS Vision 的主体抠图在本机生成，再加白色描边，可手动替换；
  - 图片只存在本机。
- **NAS 照片**：记录不排期。届时的方案是：只读挂载的 SMB 路径，本机缓存缩略图，按月份时间线展示。

## 7. 承重假设与改线条件（新增）

| 优先级 | 假设 | 如果出现什么就改线 | 最小验证 |
|---|---|---|---|
| 1 | 规范化的派发口令能让 Agent 正确接手 | 口令经常需要你手动补充 | 本项目一次真实 Claude→Codex 派发 |
| 2 | 在推进项目都维护 CURRENT | 多数项目没有 CURRENT | 状态卡降级为只看 Git 与交接文件 |
| 3 | 主力 Agent 能连接本机 MCP 读取个人说明 | 某个 Agent 不支持或不稳定 | 该 Agent 退回复制口令 + 摘要 |
| 4 | 云端能稳定运行可验证任务 | 云端环境差异导致结果不可信（见 CLOUD-SESSIONS §3） | 云端第二次基线回归；差异定位后再扩大范围 |
| 5 | 生活区模块会被你日常使用 | 上线后很少打开 | 生活区整体验收时由你判断，决定是否继续加深 |

## 8. 不做的事（本版新增）

- 不接入 Jev；判断器接口先用规则或现有模型（N5）。
- 不做 Agent 之间的自动指派，也不做未经你确认的交接（N6）。
- 不移动真实 Vault 文件（N7）。
- 随手记不写入 Obsidian。
- Agent 配置快照不上传云端。
- AI HOT 不做对外展示或转发，只用于个人非商业用途。

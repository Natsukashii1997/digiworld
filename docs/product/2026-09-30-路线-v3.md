## 2. 排序依据

按基线 v2.2 的 Q2 决定排序：先修完 R87 → 界面小调整 → 项目空间与协同 → 知识仓库 → 资产分发与 Agent 管理 → 生活区。排序时还考虑了三点：

- **先收尾在途工作**：R87 已进行一半，中途切换代价更大。
- **小而快的先做**：界面小调整都是你每天会用到的改动，风险低、反馈快。
- **承重未知放在各切片开头做最小验证**：派发口令能否让 Agent 正确接手（2.4）、Agent 能否连接本机 MCP（3.3）、云端结果是否可信（2.5）、macOS 提醒事项能否读写（5.2）。

## 3. 需要你决定的一点

**R3 · 常驻与备份放在哪里**

原路线 v2 把“常驻 + 完整备份”放在第三阶段开头，因为日历提醒和夜间运行都需要工作台一直在线。按新顺序，日历排到第五阶段，但项目状态卡、停滞雷达、可验证任务回收这些功能，在工作台开着的时候才更有用。

- **方案 1（推荐）**：常驻（开机自启、异常重启）放进第二阶段的 2.0，完整备份留在第五阶段。常驻本身很小，但它让“每天打开”这件事变得零成本。
- **方案 2**：严格按新顺序，常驻和备份都留在第五阶段。

下文按方案 1 排列。

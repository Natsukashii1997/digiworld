# 数码宝贝世界 · 深度评审与改造方案

日期：2026-10-23｜作者：Claude｜状态：**用户已确认（2026-10-23，D1–D9 全部按推荐）**，从阶段 0 开始｜运行版本：release626（5178）

> 本文回答三个问题：每个功能到底有什么价值；各板块为什么串不起来；界面为什么“好看但不好用、显得笨重”。最后给出改造方案、分阶段计划和需要你拍板的决策。
>
> 评审角度：从数码宝贝世界自身的定位、真实使用数据和世界观出发，不以其他项目为模板。

## 0. 结论先行

**一句话诊断**：七个板块各自能用，但它们之间没有共同的“东西”，也没有“去处”；数码宝贝世界观只停留在外观，不表达任何状态；工程体量又让界面背上了过多的历史包袱。

| # | 问题 | 最有力的证据 |
|---|---|---|
| 1 | **价值不清晰**：大部分板块回答不了“我为什么现在要打开它” | 首页约 38% 的宽度是装饰性的暴龙机；项目空间“在推进”里只有数码世界自己；逆向工程的开发投入最大，但只有 3 条记录 |
| 2 | **逻辑串不起来**：东西进来以后没有去处 | 13 条随手记里有 8 条是给具体项目提的需求，却没有办法交给项目；“炼入焚决”的使用次数是 0；收藏无法变成资产，也无法交给项目 |
| 3 | **UI 徒有其表**：世界观元素只负责装饰 | 伙伴固定为数码蛋，不反映任何状态；资产卡上半部 130px 只放了图标和一个没有标签的数字；项目的 3 个存档槽有 2 个是空的，占了首屏一半 |
| 4 | **UI 笨重**：信息密度低，材质与特效过多 | 每页页头约 180px；资产页首屏只能完整看到 3 张卡；7 个页面用了 5 套隐喻；样式代码里有 391 处阴影、86 组关键帧、65 种字号 |
| 5 | **工程拖累界面** | 前端 6.3 万行撑 7 个页面，其中 33 个文件已经无法从入口访问；样式分散在 59 个文件、2.15 万行；10/12 以来有 458 项改动没有提交 |

**改造主张**：让“数码宝贝世界”从**装饰**变成**结构**。

- 全站用一条主线串起来：**捕获 → 孵化 → 进化 → 出战**。每个板块都是这条线上的一个站点。
- 世界观元素只用来表达真实状态：
  - 蛋 = 还没处理的东西。
  - 进化阶段 = 使用证据。
  - 存档槽 = 在推进的项目。
  - 出战 = 交给 Agent。

**建议范围**：一轮“结构 + 界面”的深度改造，分 4 个阶段，每个阶段都由你验收。§12 列出了 9 个需要你确认的决策点。

**最关键的发现**：

- **随手记实际上是你的“项目需求收件箱”**。你在这里列牛马之家、数码世界的改版要点，再拿去交给 Agent。可是工作台不知道这条便签属于哪个项目，也不知道它有没有被处理。有两条便签（随手记贴图、焚决板块）对应的功能早就做完了，便签上却看不出来。
- **项目空间的“在推进”只认一种 CURRENT 格式**：表格里要有状态编号、当前写入者、唯一下一步这几个字段（`server/project-status.mjs:27–29`）。只有数码世界自己的 CURRENT 是这个格式。所以整条主线的终点“出战”只对它自己成立。

## 3. 诊断一：功能价值，逐板块判决

检验标准：一个板块必须回答一个明确的问题，并且放进去的东西要有去处。

| 板块 | 应该回答的问题 | 现在答得出吗 | 东西的去处 | 判决 |
|---|---|---|---|---|
| 世界总览 | 今天从哪儿开始？ | 答不出。只有计数、最近列表和装饰；唯一的动作是“记一笔” | — | **重做**为「基地」 |
| 资产仓库 | 我有什么好用的？能拿来就用吗？ | 部分能。可以搜索、可以复制，但首屏只看得到 3 张卡，复制要先打开详情 | 复制给 Agent | **保留并强化** |
| 个人收藏 | 我存过哪些好东西？ | 能存，也能看 | **没有**：变不成资产，也交不给项目 | **保留，补上去处** |
| 逆向工程 | 这个好东西怎么复刻？ | 能，但操作面像调试台（REA 版本、模型、会话、权限全部摊开） | 存成 Skill（已有） | **降级为资产的“孵化器”** |
| 项目空间 | 我在推进什么？下一步是什么？怎么交给 Agent？ | 只对数码世界自己成立；首屏是目录扫描的告警和空存档槽 | 继续 → 交接口令 | **重心改为「出战」** |
| 随手记 | 先记下来 | 能，而且是最常用的板块 | 只能炼入焚决（使用次数为 0） | **保留，补上“投递”** |
| 设置 | 授权是否安全？数据在哪？ | 能，但混着已撤下板块的授权 | — | **精简** |

还有一个藏起来的价值：工作台已经向 Agent 开放了两组只读 MCP。一组是收藏检索，另一组是个人说明和知识检索（本会话里的 `workbench-profile` 就是它）。这是数码世界和 Agent 之间**真正的连线**，但界面上只在设置里显示一行“知识开放给 Agent · 已开启”。

## 4. 诊断二：底层逻辑为什么串不起来

### 4.1 现在的连线（实测）

```
随手记 ──炼入（0 次）──▶ 焚决（在资产仓库里）
逆向工程 ──存成 Skill──▶ 资产仓库 ──复制──▶ 出了工作台，去向未知
资产仓库（规则）──装进──▶ 项目空间
个人收藏 ──（没有连线）          ……只能通过 MCP 被 Agent 只读检索
项目空间 ──继续──▶ 交接口令 ──▶ Agent（只对数码世界自己可用）
世界总览 ──读取计数── 资产、收藏；写入── 随手记
```

### 4.2 四个根因

1. **没有共同的“条目”概念，也没有“去向”**。每个板块各存各的。收藏甚至是独立的 TSX 子应用，有自己的数据目录和样式。对象之间不能互相引用，所以“这条便签交给了哪个项目”“这个资产是从哪条收藏孵出来的”都无法表达。
2. **板块按“东西的类型”划分，而不是按“东西在流程里的阶段”划分**。你脑中的流程是：想到或看到 → 变成能用的 → 在项目里用 → 越用越好。导航却是资产、收藏、逆向、项目、随手记五个并列的类型清单，流程被打散在各页的深处。
3. **主线没有终点**。项目空间只认数码世界自己的 CURRENT 格式，所以“出战”这一站对其他项目不存在。
4. **进化回路空转**。好用和需改进的反馈只有 1 次，进化阶段因此大多停在成长期或成熟期。数码宝贝世界观里最有意义的“进化”，在现实中没有燃料。

## 5. 诊断三：UI 为什么“徒有其表、笨重”

### 5.1 徒有其表：世界观元素不承载信息

| 元素 | 现状 | 问题 |
|---|---|---|
| 首页数码暴龙机 | 占内容区约 38% 的宽度，周围摆着 8 个像素徽记 | 伙伴固定为数码蛋（9/29 的决定），整块区域不反映任何状态 |
| 侧栏蛋屏 | 每 15 秒切换一次春夏秋冬，蛋在屏里翻滚 | 纯装饰，常驻在视野里 |
| 资产卡数据屏 | 卡片上半部 130px 放像素图标，左下角放一个大数字 | 那个数字是使用次数，但没有任何标签，看不出含义 |
| 项目存档槽 | SLOT 01–03，旁边有“无人持笔”的剪影 | 3 个槽里 2 个是“空存档”，占了首屏一半 |
| 页头编号 | 00、01、11、02、04、09、13 | 这是 14 个板块时代留下的编号，现在跳号，没有意义 |
| 进化阶段 | 成长期、成熟期，后面跟着 5 个小点 | 这是最有世界观意义的状态，在卡片上却是最小的元素 |

### 5.2 笨重：密度低、材质多、特效多、文案重

- **页头过重**：每页都由英文眉题、编号、成熟度徽章、48px 标题、“?”按钮和一行说明组成，约 180px。内容要到 y≈235 才开始。“?”的帮助内容和说明还有重复。
- **卡片信息顺序颠倒**：资产卡高约 350px，装饰在上，名称和用途在下，“复制”这个最常用的动作不在卡片上。1440×900 的首屏只能完整看到 3 份资产。
- **7 个页面用了 5 套隐喻**，用户每换一页都要换一次理解方式：
  - 数据屏卡片（资产）。
  - 白纸卡片摊在点阵桌面上（收藏）。
  - 胶带便签（随手记）。
  - 调试控制台（逆向）。
  - 游戏存档（项目）。
- **特效过量**：发光边框、发光按钮、扫描线、走线、漂浮微粒和季节循环同时存在。样式里有 391 处阴影和 86 组关键帧。
- **防御性文案摆在主界面**：“证据分层”“诚实状态”是对的原则，但现在以整段文字的形式出现在主界面。例如资产详情里的“已成功复制 · 未验证实际效果。计次以成功复制为准；导出保存与 Agent 实际采用尚不可确认。”，项目页常驻的黄色“结果不完整：目录深度达到上限 6……”。
- **设计令牌失控**：65 种字号、74 种圆角、108 个十六进制颜色、291 个 rgba 字面量，分布在 59 个样式文件里，文件名带着 v4、v14、v16 等层层叠加的版本后缀。每次改版都是在旧皮上再贴一层新皮，这正是“笨重”的直接来源。

## 7. 改造主张：一条主线，一个世界

### 7.1 主线：捕获 → 孵化 → 进化 → 出战

| 站点 | 世界观 | 真实含义 | 对应板块 | 现状 | 改造后 |
|---|---|---|---|---|---|
| **捕获** | 数码蛋 | 念头、刷到的好内容、想拆解的好产品 | 随手记、收藏、首页记一笔、浏览器插件、桌面悬浮便签 | 入口有 5 个，进来以后没有“待处理”的状态 | 每条捕获都是一颗“蛋”，有三种状态：待孵化、已孵化、已归档；基地汇总显示 |
| **孵化** | 破壳 | 把捕获变成能用、能交代的东西 | 统一的孵化面板 | 只有炼入焚决、逆向存成 Skill 两条路，分散在不同页面 | 四个去向：**投递到项目**、**孵成资产**、**收入焚决**、归档 |
| **进化** | 成长期 → 成熟期 → 完全体 → 究极体 | 资产被使用、获得反馈、迭代版本 | 资产仓库 | 阶段规则已有（ASSET-USAGE），在卡片上却最不显眼 | 进化阶段成为资产卡的主视觉，详情里显示进化轨迹（来源 → 版本 → 出战次数 → 反馈） |
| **出战** | 存档槽 | 在项目里交给 Agent 干活 | 项目空间 | 只对数码世界自己成立 | 存档槽放你真正在推进的项目；「继续」时一并带上投递来的需求和选好的装备（资产） |

出战的结果再回流到进化：在项目里用了哪些资产、效果如何，成为进化的证据，形成闭环。

### 7.2 统一的“去向”模型（最小数据改动）

只新增可选字段，不改已有列，也不复制正文（遵守“原件不搬家”和“不建第二套 CURRENT”）：

- **捕获条目**（随手记、收藏、逆向记录）增加 `route`：`{to: project | asset | scroll | archive, id, at}`。没有这个字段就是“待孵化”。
- **资产版本**增加 `origin`：`{kind: note | collection | reverse | manual, id}`。逆向已有的 `savedSkill` 关系直接映射过来。
- **项目登记**（工作台这一层）增加两个列表，都只存引用：
  - `inbox`：投递来的条目。
  - `loadout`：装备的资产及其固定版本。
- **「继续」生成交接口令**时附上收件条目的正文快照和装备资产的固定版本，由 Agent 写进项目**自己的** CURRENT 或派单。
  - 原条目先标「已投递 · 牛马之家 · 10/23」。
  - 交接复制成功后标「已交代」。
  - 证据分层照旧：已交代 ≠ 已完成。

### 7.3 新信息架构（推荐）

```
基地                    ← 原「世界总览」：今天从哪儿开始
── 捕获
随手记
个人收藏
── 炼化与出战
资产仓库                ← 新建 ▾：手写 / 从捕获孵化 / 从参照物逆向（原逆向工程）
项目空间                ← 存档槽 + 收件 + 装备；目录扫描清单下放到设置
──
设置                    ← 增加「对外接口」：Agent 能读什么
```

导航从 7 个减到 6 个，顺序就是主线的顺序。去掉页头编号；成熟度标记挪到帮助里。

### 7.4 世界观映射：只表达状态

| 世界观元素 | 表达的真实状态 | 出现位置 |
|---|---|---|
| 数码蛋（固定伙伴，保留 9/29 的决定） | 待孵化的数量。有待孵化时蛋会晃动，清空后安静 | 侧栏蛋屏、基地 |
| 进化阶段徽记 | 资产的使用证据阶段（沿用 ASSET-USAGE 口径） | 资产卡、资产详情、基地的主力资产 |
| 液晶屏数字 | 计数和时间：待孵化、出战中、本周出战 | 基地的暴龙机（缩小为状态屏） |
| 存档槽 | 在推进的项目（最多 3 个） | 项目空间、基地 |
| 数据飞入动效（现有） | 复制或继续成功 | 全站 |
| 孵化、进化演出 | 条目被处理、阶段提升 | 只在状态真的变化时出现 |

不承载状态的元素一律降级：季节循环改成按真实季节的静态画面；漂浮微粒、走线、扫描线默认关闭。

### 8.4 随手记

- 保留富文本、三种类型、复制、炼入，以及桌面和网页入口。
- 每条便签增加去向状态：待孵化 / 已投递 · 某项目 / 已孵成资产 / 已收入焚决。这些状态也是新的筛选项。
- 顶部动作从“炼入焚决”一个，扩展为孵化面板的四个去向。
- 你的便签多是长清单。便签的“物件感”可以保留，但长文需要更好的阅读宽度和折叠方式（见决策 D5）。

### 8.5 个人收藏

- 保留桌面摆放、分组、导入、回收和 MCP 开放。
- 增加孵化面板，四个去向和随手记一致。例如把“6 种高审美 dashboard 交互”投递给牛马之家，作为界面参考。
- **统一分类**：分组和标签二选一，作为主分类（见决策 D7）；生活类分组单独收起。
- 视觉并入主体系：白纸卡片保留，但统一色调、边框和阴影，不再像嵌入的另一个应用。

### 8.6 逆向工程（降为资产的孵化器）

- 入口从独立导航改成三处：资产仓库「新建 ▾ → 从参照物逆向」；收藏或随手记的孵化面板「拿去逆向」；保留直达地址。
- 页面主体只讲三步：**投入参照物 → 取证与任务包 → 存成 Skill**。
- REA 版本、模型、会话、权限和原生审批全部收进“引擎”抽屉，能力一个都不删。

### 8.7 设置

分成五组：
- 数据与备份。
- 授权与安全。
- **对外接口**：Agent 能读到什么（收藏检索、个人说明、知识检索），开关和最近调用都在这里。
- **目录与扫描**：原项目空间的目录管理移到这里。
- 历史授权。

已撤下板块的授权统一放进“历史授权”。

## 10. 不变的东西（底线与保留清单）

- **名字和世界**：数码世界、深色空间、橙色主色、像素图标、数码蛋固定伙伴、进化阶段口径（ASSET-USAGE），以及复制时数据飞入的动效。
- **可靠性语义**（AGENTS.md 的持续约束）：固定版本、来源追溯、revision 冲突、预览确认、写后回读、结果未知时先查询、恢复留痕。界面会变轻，但这些语义只会**下沉为公共能力**，不会删除。
- **事实源不复制**：项目 CURRENT、Obsidian 正文、Agent 配置都留在原处；项目收件只存引用。
- **已撤下的板块不恢复**（审查 601 的结论）。
- **可访问性**：控件至少 44px、320 到 1440 宽无溢出、焦点有轮廓、axe 通过。
